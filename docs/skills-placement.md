# Где держать скиллы для Claude Code и Codex

Правило: скилл лежит там же, где меняется то, что он описывает.

| | Репозиторий | Маркетплейс [`agent-plugins`](https://github.com/Cringe-Driven-Development-Team/agent-plugins) | Личный |
|---|---|---|---|
| Когда | про код этого репо | нужен в 2+ репо | только тебе |
| Claude читает | `.claude/skills/` (копия) | плагин | `~/.claude/skills/` |
| Codex читает | `.agents/skills/` (основное) | плагин | `~/.agents/skills/` |
| Установка | не нужна, `git pull` | маркетплейс + плагин, один раз | — |
| Обновление | `skills:sync` в PR с кодом | PR с версией, обновить плагин | сам |
| Примеры | `docs-site`, `docs-modules` | `cdd-tasks`, pulumi, ansible | — |

## Как выбрать

- Скилл ссылается на файлы, скрипты или тесты репозитория — в этот репозиторий: правится в том же PR, что и
  код, и не расходится с ним.
- Нужен в двух и больше репозиториях — в маркетплейс; особенности конкретного репозитория остаются в его
  `AGENTS.md` или в маленьком скилле самого репо.
- Сомневаешься — начни с репозитория; в маркетплейс перенести, когда скилл понадобится второму репо.

## Чего не делать

- Один скилл и в репозитории, и в плагине: Codex покажет его дважды
  ([openai/codex#22626](https://github.com/openai/codex/issues/22626)).
- Симлинк `.claude/skills` → `.agents/skills` вместо копии: на Windows без `core.symlinks` он молча
  становится текстовым файлом.
- Копия скилла организации в каждом репозитории: версии разойдутся.

## Правила репозитория

Не скилл, а `AGENTS.md` в корне: Codex читает его сам, `CLAUDE.md` подключает строкой `@AGENTS.md` и добавляет
только то, что касается Claude. Как это устроено в этом репозитории — раздел «Скиллы» в [`AGENTS.md`](../AGENTS.md).
