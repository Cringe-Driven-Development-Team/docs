# Сохранение открытых экранов Figma

Статус: подход выбран пользователем; короткая спецификация подготовлена к согласованию.

## Цель

При возврате к уже открытой вкладке показывать существующий iframe без повторной
навигации, инициированной документацией. Внешний вид четырёхшагового просмотрщика сохраняется.

## Проверенные факты

- База: `docs/main`, `8f3a54b`; PR #144 с четырьмя вкладками уже влит.
- `site/.vitepress/theme/FigmaEmbed.vue` сейчас меняет `src` одного iframe при выборе
  вкладки. Начальный экран — QR-код, `initialIndex=1`.
- На записи пользователя от 04.11.2026, длительность 13,854 с, выборочные кадры
  00:01–00:12 показывают белую область и индикатор загрузки при переключениях.
- Context7 и [документация Vue](https://vuejs.org/guide/essentials/conditional.html#v-show)
  подтверждают: `v-show` сохраняет DOM-элемент, меняя только CSS display.
- Существующая браузерная секция `figma` в `scripts/check-readability.ts` проверяет
  один iframe; её ожидания нужно заменить проверками жизненного цикла посещённых экранов.
- В прежнем окружении проверки живая Figma отвечала CloudFront 403; результаты с
  тестовым внешним документом не подтверждают поведение реального canvas.

## Рассмотренные подходы

1. Менять src одного iframe: минимальное удержание памяти, но повторная загрузка при возврате.
2. Загружать все четыре iframe сразу: потенциально быстрее первый переход, но тяжёлая начальная загрузка.
3. Создавать iframe при первом выборе и сохранять до ухода со страницы: выбран пользователем.
   Повторный переход использует прежний экземпляр; память расходуется на посещённые экраны.

## Поведение

- При открытии страницы создаётся только iframe начальной вкладки QR-кода.
- Первый выбор другого экрана создаёт его iframe. Непосещённые экраны не создаются
  и не инициируют загрузку.
- При переключении уже созданные iframe остаются в прежних DOM-позициях с неизменным
  src. Неактивные скрываются; выбранный становится видимым. Удаление, повторное создание
  и перемещение iframe для переключения не используются.
- Если пользователь ушёл с ещё загружающегося экрана, iframe сохраняется; при возврате
  не начинается новая загрузка по инициативе нашего компонента.
- В каждый момент виден только один экран; скрытые iframe исключены из клавиатурной
  навигации и дерева доступности. Вкладки, подпись и ссылка соответствуют активному экрану.
- Стрелки, Home/End, Tab, темы, высота и ширина просмотрщика сохраняют прежнее поведение.
- Один iframe на запись списка экранов. Для текущего списка 2FA предел — четыре;
  повторные переключения не увеличивают это число. Это не новый глобальный лимит компонента.
- Время жизни сохранённых экранов ограничено экземпляром просмотрщика: при уходе
  на другую страницу все iframe удаляются, ссылки/обработчики компонента не удерживают их.
  Возврат на страницу начинает с QR и нового набора посещённых экранов. Переход к якорю
  на той же странице сам по себе не сбрасывает просмотрщик.
- Кэш в localStorage, сохранение между перезагрузками, предварительная загрузка всех
  экранов и автоматическое вытеснение посещённых экранов не добавляются.

Это решение заменяет требование «один iframe в DOM» из спеки четырёхшагового
просмотрщика. Визуально остаётся один просмотрщик с четырьмя вкладками.

## Память и ограничения

Скрытый iframe продолжает занимать память и может выполнять фоновые задачи Figma.
Ограничение числа экземпляров предотвращает их накопление из-за наших переключений,
но не доказывает отсутствие утечек внутри стороннего приложения и не гарантирует
конкретного объёма памяти. Обещание — отсутствие инициированной нами перезагрузки
сохранённого экрана; браузер и Figma могут самостоятельно освобождать или обновлять ресурсы.

## Приёмка

- До выбора других вкладок есть только QR iframe и нет запросов остальных экранов.
- После первого посещения всех вкладок есть четыре iframe и только один видимый.
- При многократных возвратах сохраняются те же DOM-узлы и контексты iframe; тестовый
  документ сохраняет маркер состояния, а счётчик его навигаций/загрузок не растёт.
- Проверены быстрые переключения, в том числе до завершения загрузки предыдущего экрана.
- При SPA-переходе на другую страницу iframe и их дочерние browsing contexts исчезают;
  повторное посещение создаёт только QR. Повторные циклы входа/выхода не накапливают контексты.
- Проверены доступность и отсутствие фокуса в скрытых экранах, обе темы, мобильная
  и настольная ширины, узкий режим чтения и адрес превью ветки.
- Отдельно измеряется память при доступной живой Figma: после первого экрана, после
  четырёх, после повторных переключений и ухода. Указывается область измерения;
  heap только родительской страницы не выдаётся за память всех cross-origin iframe.
  Если Figma недоступна, это ограничение фиксируется, измерения заглушки её не заменяют.

## Область изменений

Компонент `FigmaEmbed.vue` и проверки его жизненного цикла в существующей браузерной
секции. Контент сценариев, список макетов, node-id и файл Figma не меняются.
Новые зависимости не требуются. План реализации составляется после согласования спеки.
