# Таблица cookie сессии в документации CSRF

## Цель

Сделать атрибуты cookie в разделе «Cookie сессии» страницы
`site/documentation/security/csrf.md` удобными для просмотра, сохранив смысл текста.

## Подходы

Выбран пользователем существующий формат из трека BFF: обычная Markdown-таблица
«Атрибут — Значение». Она разделяет параметры cookie и пояснения их поведения.
Текущий перечень внутри абзаца хуже просматривается; третья колонка с объяснениями
дублировала бы последующий текст и расширяла таблицу. Новые компоненты не нужны.

## Оформление

Перед таблицей — короткий абзац: BFF хранит токены Go и сроки их действия
в cookie, шифрует содержимое AES-256-GCM; JavaScript страницы не получает
открытые токены и не читает cookie.

| Атрибут | Значение |
| --- | --- |
| Имя | `__Host-Http-session` |
| `HttpOnly` | да |
| `Secure` | да |
| `Path` | `/` |
| `SameSite` | `Lax` |
| `Domain` | не задаётся |

После таблицы сохраняются объяснения `HttpOnly`, `Secure`, ограничения `SameSite=Lax`
и различия site/origin, а также вызов `/api/trpc` с `credentials: 'same-origin'`.
Редактура касается только этого раздела; даты и источники проверки остаются прежними.

## Проверенные факты

На docs/main `8f3a54b` текущий раздел уже содержит перечисленные атрибуты,
шифрование и пояснения. Образец таблицы находится в
`site/modules/2/tracks/bff/auth.md`, в разделе «Cookie сессии».
Это изменение представления существующих сведений, а не новая проверка прода.

## Приёмка

В собранной странице видны шесть строк таблицы с указанными значениями;
пояснения до и после неё сохранены. Таблица читается на desktop и mobile.
Выполняются штатные проверки типов, тесты и сборка сайта.
Отдельный тест, фиксирующий точную редактуру абзацев, не требуется.
