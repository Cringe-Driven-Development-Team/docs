# OpenWiki как первый источник контекста

Статус: согласовано владельцем; уточнено допущение об актуальности публикуемой wiki.

## Зачем

Агент должен получать достаточный ответ из OpenWiki без обязательного повторного
поиска по исходникам. Сейчас общие требования перепроверять факты и проверять
свежесть перед использованием wiki приводят к лишней работе.

## Согласованное поведение

Когда задаче нужен поиск контекста:

1. Начать с `openwiki_search` в нужном пространстве.
2. Прочитать подходящий раздел через `openwiki_read`, передав ID wiki из результата.
3. Если ответ достаточен и нет противоречия,
   остановить поиск. Не перечитывать канонический документ только ради перепроверки.
4. Открыть конкретный исходник при пробеле, противоречии
   либо непосредственно для внесения изменений.

Для обычного чтения опубликованная wiki считается актуальной: это согласованное
допущение процесса, а не обязанность читающего агента устанавливать её свежесть.
Агент не запускает `wiki:check`, `git fetch` и не сравнивает SHA ради получения ответа.
Поддержание актуальности относится к процессу обновления и публикации; целевая
модель владельца — обновление через CI. Существующие проверки свежести сохраняются
для обслуживания и генерации wiki, CI и явных запросов пользователя. Явные ошибки
инструмента или противоречащие сведения не игнорировать.

Если MCP недоступен, читать `openwiki/quickstart.md` и нужную Markdown-страницу.
Если wiki отсутствует или не дала нужных сведений, искать в соответствующем
каноническом документе или репозитории. Для простой правки известного файла
предварительный поиск по wiki не обязателен. Не загружать все wiki при старте.

## Подход

Согласован принцип: достаточный ответ wiki завершает поиск; автоматическую
перепроверку после каждого изменения файлов не добавляем.

Предлагаемая реализация — одинаковое правило в `AGENTS.md` четырёх репозиториев
и согласованные инструкции генерации `openwiki/INSTRUCTIONS.md`. Это распространяет
правило со штатным обновлением репозиториев и сохраняет его при генерации quickstart.

Правка только локального глобального скилла не подходит: студенты её не получат,
а переустановка пакета может её затереть. Новый MCP, обёртка и новый скилл не нужны.

## Границы изменений

- Уточнить инструкции `docs`, `frontend`, `backend`, `infra` вне управляемых
  установщиком блоков. Удалить противоречащие общие требования всегда проверять исходники.
- Согласовать активные пояснения в README и странице владельцев сведений там,
  где они требуют обязательного дублирования поиска. Исторические спеки не переписывать.
- Сохранить требования проверять источники при редактировании канонических страниц,
  схем, кода и контрактов. Скиллы `docs-site` и `docs-modules` не ослаблять.
- Wiki описывает состояние на момент генерации. Для ответа о состоянии прода
  прямо сейчас нужны соответствующие свидетельства или проверка стенда.
- Планы модулей остаются вне корпуса docs wiki; читать их напрямую по запросу о планах.
- Настройка автоматической генерации через CI — отдельная задача. Не описывать её
  как уже работающую и не менять действующие workflows, токены или запуск модели
  в этой правке. Сведения о текущем ручном запуске сохранять в эксплуатационных
  инструкциях, не превращая их в требование проверять wiki перед чтением.
- В рамках правки инструкций не менять сгенерированные страницы и контрольные
  отметки; обновление содержимого выполняется отдельно от исходного PR.

## Проверенные факты

- В `docs/AGENTS.md` есть обязательная проверка свежести перед использованием wiki.
- В платформенных `AGENTS.md` найдены широкие требования проверять факты по исходникам.
- Все четыре корпуса свежести учитывают `AGENTS.md` и `openwiki/INSTRUCTIONS.md`:
  изменение этих файлов сделает существующие wiki устаревшими по штатной проверке.
- Общий workspace уже поддерживает поиск и чтение wiki разных репозиториев;
  изменение MCP или визуализатора для этой задачи не требуется.

## Приёмка

Проверить инструкции на пяти сценариях: достаточный ответ wiki; пробел;
противоречие; редактирование исходника; недоступный MCP.
В первом сценарии агент завершает поиск после чтения wiki, в остальных переходит
к необходимому конкретному источнику или Markdown. Отдельно проверить, что вопрос
о состоянии прода прямо сейчас не превращается в неподтверждённое утверждение:
актуальная wiki с описанием архитектуры сама по себе не является мониторингом.

Новые программные тесты и изменения runtime не нужны. Перед коммитами выполнить
предписанные соответствующим репозиторием проверки; общий поиск формулировок
должен подтвердить отсутствие противоречий в активных инструкциях.
