# Короткий лоадер статьи со схемами

## Цель и выбранный подход

При открытии статьи со схемами читатель видит короткое состояние загрузки,
затем сразу содержимое с готовой видимой схемой и правильным положением якоря.
Промежуточные изменения размеров и автоматическая прокрутка проходят под лоадером.
Это небольшое дополнение к общему просмотрщику из PR134.

Владелец выбрал короткий лоадер статьи. Второй рассмотренный подход — локальные
лоадеры с расчётом размеров схем при сборке: текст доступен сразу, но потребуется
менять сборку и передавать размеры в HTML. Для текущего запроса выбран первый,
с меньшим объёмом изменений. Один спиннер внутри растущего блока проблему не решает.

## Проверенные факты

- База: docs `b0b1b2101f289fedd23bfe33f8bb64e61674b481`.
- Запись владельца `bandicam 2026-11-02 22-01-49-625.mp4`, 2,611 с,
  без звука: около 1-й секунды виден существующий текст «Загрузка схемы…»,
  затем меняются высота карточки и положение раздела StaleWhileRevalidate.
- `MermaidFrame.vue` сначала передаёт `size=null`; `DiagramFrame.vue` задаёт
  `min-height:320px`. Скрытый через opacity исходник продолжает влиять на высоту.
  После SVG устанавливается натуральная геометрия с ограничением 70vh.
- Локальная трассировка matching nested build, 2560×1440, fresh/reload:
  высота целевой рамки проходит 730 → 320 → 1222 → 1008 px;
  заголовок после первой прокрутки смещается и позднее возвращается к шапке.
  Свидетельство: `.superpowers/mermaid-loading-recon/{fresh,reload}.json`.
- `scrollToHashAfterMermaid` в `theme/index.ts` уже учитывает сохранённую ширину,
  шапку и отмену при действии читателя. Его текущая проверка всех `.mermaid`
  не подходит для готовности статьи: схемы вне экрана остаются lazy.

## Поведение

1. Лоадер действует при первом открытии, reload и переходе на другую статью
   с Mermaid. Статьи без Mermaid открываются обычным образом. Смена темы,
   масштабирование и переход по якорю внутри уже открытой статьи лоадер не включают.
2. На месте области статьи и её оглавления — фон текущей темы и небольшой
   индикатор с текстом «Загрузка статьи…». Шапка и боковая навигация доступны.
   Содержимое остаётся смонтированным и сохраняет геометрию для lazy-renderer.
   Промежуточная статья не должна успевать мелькнуть до лоадера.
3. Готовность означает: применена сохранённая ширина чтения, готовы шрифты,
   целевой якорь установлен под шапкой, схемы в текущей видимой области получили
   SVG и начальный transform просмотрщика. Проверка включает ближайшую область
   предварительной загрузки renderer, чтобы соседняя схема не сдвинула первый кадр.
   После завершения текущих изменений геометрия должна стабилизироваться.
4. Лоадер снимается без искусственной минимальной задержки и без анимации
   перемещения статьи. Схемы далеко за экраном продолжают загружаться при прокрутке.
   После раскрытия статьи отложенная коррекция якоря не должна снова двигать её.
5. Предлагаемый мной предел ожидания — **5 секунд**. При ошибке схемы или
   истечении предела показываем статью и существующее локальное сообщение ошибки;
   незавершённая схема может продолжить загрузку. При действии читателя подготовка
   не должна бороться с его прокруткой. При уходе со страницы подготовка отменяется;
   старый callback не может скрыть или раскрыть следующую статью.
6. Без JavaScript текст остаётся доступным. Ошибка загрузки основного приложения
   также не должна оставлять статью навсегда под лоадером. Состояние ожидания
   доступно скринридеру (`role=status`, `aria-busy`); индикатор учитывает
   `prefers-reduced-motion`. Никакой блокировки body или перехвата фокуса.

## Визуальный образец и решения

Основной образец — текущая страница из записи владельца и CSS темы просмотрщика.
Вспомогательное правило — `refero-design/references/motion.md`: только функциональное
движение и вариант reduced-motion. Новый стиль сайта и отдельный макет не требуются.

| Решение | Основание |
| --- | --- |
| Фон и текст из существующих VitePress CSS-переменных, обе темы | Текущий сайт и запись |
| Небольшой индикатор и одна строка в области статьи | Выбранный короткий лоадер, без процента неизвестной загрузки |
| Содержимое сохраняет размеры и DOM во время ожидания | Проверенная работа lazy renderer и якорей |
| Раскрытие без движения макета, reduced-motion для индикатора | Цель владельца и motion reference |

## Границы и проверка

Изменения локальны теме сайта и её проверкам. Новые зависимости, доработка форка,
предварительный расчёт SVG, изменение исходников 50 схем и ожидание всей страницы
не требуются. Управление общим просмотрщиком сохраняется.

Проверить fresh/reload/SPA, прямой якорь StaleWhileRevalidate, страницу без якоря,
узкий сохранённый режим, 390px, обе темы; искусственно задержанные SVG/приложение,
ошибку/таймаут, быстрое переключение страниц, действие читателя и reduced-motion.
Наблюдать не только конечный SVG: записывать видимость статьи, геометрию и scrollY
с начала документа. В обычном успешном сценарии после раскрытия статьи скачков нет.
По таймауту приоритет — доступность текста; устранение всех последующих сдвигов
при незавершённой загрузке этим вариантом не гарантируется.

Исполнителю остаются выбор минимального механизма начального состояния до первого
кадра, переиспользование существующей коррекции якоря и короткий критерий стабилизации.
Искусственный таймер вместо проверки готовности не подходит.
