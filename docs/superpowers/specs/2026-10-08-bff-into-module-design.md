# Документация BFF — в трек модуля; модули — план, остальное — прод

Дата: 2026-10-08. Статус: дизайн утверждён в чате, ждёт ревью спеки.

## 1. Цель

У каждой темы одна точка правды, и по разделу сайта сразу видно, прод это или план.

- **Модули** (`/docs/modules/`) — то, что ещё не сделано и будет реализовано: план модуля, треки,
  проектные документы треков.
- **Остальные разделы** («Архитектура», «Безопасность», дальше другие) — как работает прод сейчас.

Сейчас про BFF две точки правды, и они уже разошлись: раздел `/docs/bff/` (три страницы проекта
миграции) и трек `bff` модуля октября (`/docs/modules/2026-10/tracks/bff`). У трека в подзадачах
«tRPC», а раздел пишет, что tRPC в трек не входит.

Успех:

- три страницы `/docs/bff/` открываются как страница трека `bff` и две его подстраницы;
  пункта «BFF» в верхнем меню нет;
- старые адреса `/docs/bff/`, `/docs/bff/contract`, `/docs/bff/auth` переводят на новые с тем же якорем;
- правило «модули — план, остальное — прод» записано в `CLAUDE.md`, `README.md` и на странице «Модули»;
- решение по tRPC записано в треке, устаревшие из-за него места помечены.

## 3. Решения

| Решение | Почему | Отвергнуто |
| --- | --- | --- |
| Модули — план, остальные разделы — прод | одна точка правды; по разделу видно, прод это или план | проектные разделы вне модулей с плашкой «не внедрено» |
| Сделанный трек замораживается в архиве модуля как история; прод описывается заново в разделе вне модулей | видно, что планировали и что вышло; раздел прода пишется по коду | перенос документа трека в раздел прода; трек вне модулей |
| Подстраницы трека — `tracks/<id>/<page>.md` рядом с `tracks/<id>.md` | треки без подстраниц не меняются; читалка уже пропускает подкаталоги | одна длинная страница (~850 строк, 10 mermaid); трек-каталог `tracks/<id>/index.md` (менять все 19 треков и адреса) |
| Порядок подстраниц — список `pages` во frontmatter трека | порядок задаёт автор, лишний или потерянный файл ловит сборка | порядок по алфавиту файлов |
| Старые адреса — статические страницы-переадресации в `dist/bff/` | как `/docs/diagrams/`; якорь сохраняется; без JS — ссылка | страницы VitePress с переадресацией (попадают в поиск и меню) |
| tRPC — для всего между клиентом и BFF, переключение разом | смысл BFF — API под UI; один способ звать сервер; проект учебный, пользователей нет (`CLAUDE.md`, «Проект») | tRPC только для собственных ручек BFF; поэтапный переезд через прокси |
| Переработка «Контракта» и «Авторизации» под tRPC — отдельный PR | эта задача про структуру сайта | всё в одном PR |
| «Схемы корня описывают прод» | правило «вне модулей — прод» касается и схем | схемы — целевое состояние |

Решение «tRPC отвергнут» из спеки `2026-10-08-bff-migration-docs-design.md` отменено; сама спека
не правится — спеки хранят историю решений.

## 4. Правило в документации

**`CLAUDE.md`:**

- новый раздел «Что где лежит» (после «Проект»):
  - модули (`site/modules/`) — то, что ещё не сделано: план, треки, проектные документы треков;
  - остальные разделы сайта и схемы корня — как работает прод; утверждения о коде — со ссылкой на
    файл и строку на SHA;
  - трек сделан — его страницы не правятся, сверху плашка `::: info` «Сделано. Как работает сейчас —
    [раздел]»; прод описывается или переписывается в разделе вне модулей.
- «Схемы описывают целевое состояние» → «Схемы корня описывают прод».
- строка про модули в «Сборке»: трек — `tracks/<id>.md`, подстраницы — `tracks/<id>/<page>.md` и
  список `pages` во frontmatter трека.

**`README.md`:** в разделе «Модули» — то же правило абзацем и подстраницы трека в описании формата
(пример frontmatter с `pages`).

**`site/modules/index.md`:** под вводной фразой — «Здесь план: что ещё будет сделано. Как работает
прод — [Архитектура](/architecture/) и [Безопасность](/security/csrf/).»

## 5. Подстраницы трека

### 5.1. Данные

```
site/modules/<YYYY-MM>/tracks/
  <id>.md              ← трек; во frontmatter необязательный pages: [<page>, …]
  <id>/<page>.md       ← подстраница; во frontmatter обязателен title
```

- `pages` — список id подстраниц в порядке показа; id — как у трека: строчная латиница, цифры, дефис.
- В модели: `Track.pages: TrackPage[]`, `TrackPage = { id, title, url }`,
  `url = /modules/<module>/tracks/<id>/<page>`. Без `pages` — пустой список.
- `parseTrack` разбирает `pages` (список строк, формат id); `readModules` читает каталог
  `tracks/<id>/`, берёт `title` из frontmatter подстраниц и проверяет соответствие.

### 5.2. Проверки при сборке

Ошибки — `ModuleDataError` с путём от `site/`, как остальные проверки модулей:

1. `pages` не список строк или id не по формату — `modules/2026-10/tracks/bff.md: pages — …`.
2. id из `pages` без файла — `modules/2026-10/tracks/bff.md: pages — нет файла bff/contract.md`.
3. md-файл в `tracks/<id>/`, которого нет в `pages`, или каталог `tracks/<id>/` у трека без `pages` —
   `modules/2026-10/tracks/bff/x.md: pages — подстраницы нет в pages трека bff.md`.
4. У подстраницы нет непустого `title` — `modules/2026-10/tracks/bff/contract.md: title — …`.
5. Повтор id в `pages`.

Каталог `tracks/<id>/` без трека `<id>.md` — ошибка по п. 3.

### 5.3. Навигация

- **Меню модулей** (`config.mts`): у трека с подстраницами — вложенные пункты
  `{ text: t.title, link: t.url, items: t.pages.map(…) }`, раскрыты.
- **`pageRef`** узнаёт подстраницу: `modules/<m>/tracks/<t>/<p>.md` → `{ module, track, page }`.
  Большую шапку `TrackMeta` рисует, только когда `page` нет.
- **`TrackMeta`:**
  - на странице трека с подстраницами — строка «Документы» в списке `dl` со ссылками на подстраницы
    (на телефоне меню скрыто);
  - на подстранице — без большой шапки, одна строка над h1: «Трек <название> · <модуль> · На графе
    модуля» со ссылками на трек, модуль и граф.
- Граф модуля не меняется: подстраницы не узлы.

### 5.4. Переадресация старых адресов

- `scripts/build-index.ts`: `BFF_REDIRECTS` — `bff/index.html` → `../modules/2026-10/tracks/bff`,
  `bff/contract.html` → `../modules/2026-10/tracks/bff/contract`, `bff/auth.html` →
  `../modules/2026-10/tracks/bff/auth`; функция страницы-переадресации: `noindex`,
  `location.replace(цель + location.hash)`, ссылка «Страница переехала» для чтения без JS.
- Пишутся там же, где `INDEX_FILE`: `build-index.ts` (шаг `index`) и `build-site.ts`. Попадают в
  `protectedFiles`, чтобы VitePress их не перезаписал.
- Пути относительные — работает и в превью веток (`/docs/branches/<slug>/bff/…`).
- Имена не пересекаются с файлами замороженных схем `bff/*.html` — проверяет тест.
