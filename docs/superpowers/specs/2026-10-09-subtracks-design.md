# Подтреки и вложенные подзадачи в графе модуля

## 1. Цель

Трек может быть частью другого трека: «Harness фронта» — часть «Harness сервиса». У подзадачи могут быть
свои подзадачи: «Скиллы» → «/apidog». Сейчас граф этого не умеет, и связь приходится записывать
`related` с пояснением «подтрек», а вложенную подзадачу — одной строкой «Скиллы: /apidog».

Готово, когда:

- подтрек задаётся одним полем во frontmatter подтрека и на графе висит на родителе сплошной линией;
- прогресс родителя считает и задачи подтреков;
- подтрек вложен в пункт родителя в меню и в списке треков под графом;
- вложенная подзадача — свой узел на графе, связанный с подзадачей-родителем;
- `front-harness` и `service-harness` переведены на новую запись.

## 2. Проверенные факты

На ветке `docs/tracks-split`, коммит `87ac7c2`.

- Граф рисует [`force-graph`](https://github.com/vasturiano/force-graph) `1.51.4` (`package.json`):

  (`modules.ts:278-281`), id подзадачи `subtask:<трек>/<индекс>`; `related` — только если видны оба трека

## 3. Решения

- Вложенность — **один уровень**: у подтрека нет своих подтреков, у вложенной подзадачи нет своих
  подзадач. Примеры «Harness сервиса» → «Harness фронта» и «Скиллы» → «/apidog» в это укладываются.
- Подтрек ссылается на родителя полем **`part_of`** у себя. Имя не `parent`: оно занято родительской
  задачей на доске. Новый подтрек добавляется без правки файла родителя.
- Прогресс родителя — **сумма** его задач и задач его подтреков. Задача по-прежнему у одного трека,
  двойного счёта нет.
- Подтрек — обычный трек: свои исполнители (от родителя не наследуются), свой вариант в поле «Трек» на
  доске, своя страница по прежнему адресу.

## 4. Данные

### 4.1. Frontmatter

```yaml
# tracks/front-harness.md
part_of: service-harness
```

```yaml
# tracks/service-harness.md
subtasks:
  - title: "Скиллы"
    subtasks: ["/apidog"]
  - "Ещё подзадача"        # строкой — как сейчас
```

### 4.2. Модель — `site/.vitepress/modules.ts`

```ts
export type Subtask = { title: string; subtasks: string[] };
export type Track = {
  // …как сейчас, кроме:
  subtasks: Subtask[];
  partOf?: string;
};
```

Подзадача строкой читается как `{ title, subtasks: [] }`: существующие треки не меняются.

### 4.3. Проверки при сборке

Ошибка — `ModuleDataError` в нынешнем формате `<файл>: <поле> — <что не так>`.

| № | Правило | Поле | Текст ошибки |
| --- | --- | --- | --- |
| 1 | `part_of` — непустая строка | `part_of` | `нужна непустая строка` |
| 2 | трек `part_of` есть в модуле | `part_of` | `трека <id> нет в модуле <модуль>` |
| 3 | `part_of` не на себя | `part_of` | `трек ссылается сам на себя` |
| 4 | родитель сам не подтрек | `part_of` | `<id> сам подтрек: вложенность — один уровень` |
| 5 | между подтреком и родителем нет `related` | `related[i].track` | `<id> — родитель или подтрек, связь уже есть через part_of` |
| 6 | подзадача — строка или объект `{ title, subtasks }` без других ключей; `subtasks` можно не указывать — тогда `[]` | `subtasks[i]` | `нужна строка или { title, subtasks }` |
| 7 | `title` — непустая строка | `subtasks[i].title` | `нужна непустая строка` |
| 8 | вложенные подзадачи — только строки | `subtasks[i].subtasks[j]` | `нужна строка: вложенность — один уровень` |
| 9 | названия соседних подзадач не повторяются (на уровне трека и внутри одной подзадачи) | `subtasks` | `подзадача «<название>» повторяется` |

Правила 2–5 — в `parseModule`, после чтения всех треков; 1, 6–9 — в `parseTrack`. Правило 5 срабатывает
в обе стороны: `related` от подтрека к родителю и от родителя к подтреку.

## 5. Граф

### 5.1. Узлы и связи — `buildGraph`

- Новый вид связи `sub`: родитель → подтрек. Строится, если видны оба трека, как `related`.
- Вложенная подзадача — узел `kind: "subtask"`, id `subtask:<трек>/<i>/<j>`, связь `part` от узла
  `subtask:<трек>/<i>`. У узла — `trackId` трека.
- Слой «Подзадачи» (`hide=subtasks`) скрывает и вложенные подзадачи. Связь `sub` — структура, а не слой:
  слой «Связи между треками» скрывает только `related`.
- Родитель скрыт фильтром по людям или направлению — подтрек остаётся без связи `sub`.

### 5.2. Отрисовка — `GraphCanvas.vue`

- `sub` — сплошная линия, толщина и цвет как у `part`; длина 45.
- Вложенная подзадача — тот же узел подзадачи, радиус 2.6.

### 5.3. Соседи — `neighbours`

Прямые соседи работают сами: родитель ↔ подтрек, подзадача ↔ вложенная подзадача. У человека к
подзадачам его треков добавляются и их вложенные подзадачи.

### 5.4. Карточка узла — `NodeCard.vue`

- **Трек:** «Подзадачи · N» — подзадачи первого уровня, у каждой вложенные списком под ней; у подтрека —
  строка «Входит в трек» с кнопкой родителя; у родителя — блок «Подтреки» (см. §6).
- **Подзадача первого уровня:** как сейчас, плюс «Подзадачи» — её вложенные, кнопками.
- **Вложенная подзадача:** «Входит в подзадачу» (кнопка подзадачи-родителя), «Входит в трек», «Кто».
- `:key` в списках подзадач — индекс, а не строка.

## 6. Прогресс и задачи

- Новая функция в `site/.vitepress/board.ts`:

  ```ts
  /** Задачи трека и его подтреков; у подтрека и обычного трека — только свои. */
  export function tasksWithSubtracks(module: Module, byTrack: Readonly<Record<string, BoardTask[]>>, id: string): BoardTask[];
  ```

  `trackProgress` не меняется.
- Кольцо прогресса на узле родителя (`ModuleGraph.vue`, `progress`) — по `tasksWithSubtracks`.
- Карточка родителя и его страница (`TrackMeta.vue`): заголовок «Задачи · X из Y готово» — по
  `tasksWithSubtracks`; список задач — только свои; блок «Подтреки» — каждый подтрек со своим
  «a из b готово» и ссылкой (в карточке — кнопка узла, на странице — ссылка на страницу подтрека).
- Карточка подтрека и его страница — как у обычного трека плюс «Входит в трек: <родитель>».
- Доска не меняется: `board sync` кладёт в «Трек» все треки; наследование трека от родительской задачи —
  как сейчас.

## 7. Навигация

- `moduleSidebar`: подтрек — пункт внутри пункта родителя, после подстраниц родителя; у подтрека с
  подстраницами — свои вложенные пункты. На верхнем уровне подтрека нет. Пункт родителя без подстраниц,
  но с подтреками — `collapsed: false`.
- `TrackList.vue`: подтрек — вложенный пункт под родителем, в группе направления родителя, даже если
  направление подтрека другое. В группе своего направления он не повторяется.
- `TrackMeta.vue`: «Подзадачи» — вложенным списком.
- Адреса страниц не меняются.
- `personLoad` не меняется: подтрек — отдельный трек своих исполнителей.

## 11. Не входит

- Вложенность глубже одного уровня.
- Подтрек из другого модуля.
- Наследование исполнителей от родителя.
- Изменения доски и `board sync`.
