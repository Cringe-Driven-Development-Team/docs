# Подготовка офлайн-режима через BFF

## Цель и границы

Дополнить архитектурную страницу модуля №2: показать, где инициируется регистрация SW,
кто раздаёт файлы и когда офлайн-комплект попадает в кеш. Сохранить учебное объяснение
без готового SW, конфигурации плагина или псевдокода реализации. Изменения продолжают уже влитый PR #115 отдельным PR.

## Подходы и выбор

После исследования браузерных требований и Context7 обсудили раздачу SW самим BFF
и раздачу через Caddy, включая внутреннее проксирование к CDN. Пользователь выбрал BFF.
Публичный стабильный адрес SW — `https://cellestial.ru/sw.js`, scope — `/`.
CDN-бандл SPA может инициировать регистрацию в контексте страницы на cellestial.ru.

Согласовано: офлайн-HTML и его обязательные ресурсы тоже раздавать через публичную
статику BFF: `https://cellestial.ru/offline.html`. Без сессии, обращения к Go API и bootstrap.
Основные JS/CSS SPA продолжают загружаться из CDN.

## Схемы и текст

Добавить перед обычным онлайн-сценарием раздел «Подготовка офлайн-режима» с отдельной
Mermaid-схемой. Итого станет 14 схем: прежние 10 теории и 4 архитектуры.
Схема разделяет страницу SPA, браузер/SW, публичную раздачу BFF и Cache Storage:
страница инициирует регистрацию; браузер получает sw.js; во время установки SW заранее
получает offline.html и нужные ему ресурсы от BFF и сохраняет их в Cache Storage.
Регистрация сама по себе не гарантирует готовность: установка/кеширование могут не завершиться,
а активация и управление страницами имеют собственный жизненный цикл.

Подписать источники и полные адреса в тексте. Публичные файлы BFF отделить от обработчика
персонального HTML. Уточнить, что CDN base JS/CSS не должен менять URL регистрации SW;
конкретные настройки плагина остаются работой студента.

## Явная политика кеширования

В таблице «Что кешируем» добавить отдельный столбец «Кешируем в Cache Storage»;
каждая ячейка этого столбца содержит только «Да» либо «Нет».

| Ресурс | Кешируем в Cache Storage |
| --- | --- |
| Навигационный HTML BFF | Нет |
| RPC / API | Нет |
| Офлайн-страница | Да |
| Обязательные ресурсы офлайн-страницы | Да |
| Остальные JS/CSS SPA и ассеты CDN | Нет |

Последняя строка — согласованная политика минимального выбранного сценария;
обычное HTTP-кеширование браузером остаётся отдельным механизмом.
Сам sw.js устанавливается и сохраняется браузером как Service Worker;
это не запись приложения в Cache Storage и не обязанность кешировать sw.js своим SW.
