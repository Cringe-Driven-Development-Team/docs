# Миграция интерактивных схем Mermaid

Статус: пользователь утвердил спеку 2026-11-01; пользователь выбрал superpowers:executing-plans.

## Цель

Перевести сайт с `vitepress-plugin-mermaid` на `vitepress-mermaid-renderer`.
Пользователь выбрал интерактивные схемы с масштабированием и полноэкранным просмотром.
Устранить краткое появление `Syntax error` при загрузке корректных схем и сохранить
работоспособность якорей, тем и настроек чтения.

## Проверенные факты

- На момент подготовки локальный main и удалённый main совпадают: `1d5b72e6e3101375663df1c322e21dec93efdc5d`.
  PR130 с удалением Inline Link Preview завершён; он не входит в эту миграцию.
- В проекте VitePress `2.0.0-alpha.21`, старый плагин `2.0.17`, Mermaid 11;
  подключение находится в `site/.vitepress/config.mts`, CSS и ожидание Mermaid перед
  коррекцией якоря — в `site/.vitepress/theme/`.
- Диагностика продовой `modules/2/tracks/offline/caching-strategies#networkonly`
  зафиксировала автоматический `mermaid.run()` на `window.load`: он получает пять
  пустых `.mermaid` до поздней инициализации старого плагина. Затем явный render
  заменяет ошибку правильными схемами. Ошибка временная и не попадает в console/page errors.
  Причинная связь с удалением Inline Link Preview не установлена.
- Изученный снимок исходников нового renderer версии `1.2.3` поддерживает Mermaid 11,
  `createMermaidRenderer`, строгий режим, обновление темы, масштабирование и fullscreen.
  Он читает обычные fences VitePress и создаёт `.mermaid-wrapper` / `.mermaid-container`.
- Новый renderer откладывает схемы вне экрана через IntersectionObserver с запасом 200px;
  доступного выключателя lazy rendering в изученных options нет. Его пример использует
  VitePress 1; совместимость с нашей версией и устранение гонки пока не проверены.
- Текущий browser CLI проверяет финальные `.mermaid svg`; этого недостаточно для
  временной ошибки или ещё не созданных lazy-схем. На сайте 44 исходных Mermaid-блока.

## Подходы и выбранное решение

Целевая библиотека уже выбрана для продолжения миграции. Для режима схем рассмотрены
статичный SVG с горизонтальной прокруткой и интерактивный renderer. Пользователь выбрал
второй: ему нужны масштабирование и полноэкранный просмотр. Mermaid остаётся на версии 11.

Интеграция использует штатные компоненты и CSS нового renderer, без собственной панели
или форка зависимости.

Дополнение от 2026-11-02: после подтверждённого дефекта lifecycle пользователь прямо
поручил форкнуть библиотеку и доработать её. По уточнению владельца форк размещается в личном аккаунте YarikMix; разрешены исправление
исходников и подключение проверенного неизменяемого коммита форка; прежнее ограничение
на форк для этой задачи отменено. Самостоятельная панель управления по-прежнему не нужна. В панели нужны увеличение, уменьшение, сброс вида и fullscreen;
схему можно перемещать при увеличении. Подписи кнопок — по-русски через API локализации.
Выбор встроенного способа fullscreen остаётся исполнителю: проверить открытие и выход,
включая Escape, и возврат к тому же месту страницы без сброса настроек чтения.

Начальный вид должен позволять прочитать схему и приблизить детали; подписи не обрезаются,
диаграмма и панель не расширяют всю страницу на мобильном экране. Штатную раскладку
renderer используем без отдельного редизайна. Копирование и скачивание не добавляем.

## Объём изменений

- Заменить зависимость и lockfile, убрать старый `withMermaid` и его настройки из config.
  Инициализацию и реакцию на смену темы перенести в существующую тему VitePress;
  сохранить `securityLevel: strict`, перенос длинных сообщений и Mermaid 11.
- Адаптировать только относящийся к Mermaid CSS. Проверить необходимость старого
  `optimizeDeps.include` по результату dev/build, а не удалять его механически.
- Сначала измерить якоря с новым renderer. При воспроизводимой необходимости минимально
  исправить существующее ожидание готовности, учитывая исходные fences и lazy-схемы.
  Не ждать бесконечно всех схем вне экрана, не считать пустую выборку готовностью
  и не перехватывать намеренную прокрутку читателя или более новый переход.
- Адаптировать существующий `scripts/check-readability.ts`: новый DOM, посещение lazy-схем,
  проверки интерактивности и наблюдение ошибок с document-start через всю загрузку.
  Обновить активный docs-site, если меняются описанные в нём правила проверки.

Исходники схем, Markdown страниц, данные модулей, маршруты и ID заголовков сохраняются.
Eraser/Diagram, его iframe и `@panzoom/panzoom`, Tabs, Group Icons, Enhanced Readabilities,
FullWidth по умолчанию и сохранённый узкий режим остаются рабочими.

## Проверка и приёмка

- Типы, unit-тесты, `modules:check`, проверка синтаксиса всех исходных Mermaid и сборка.
  Без Docker использовать `DIAGRAMS_NATIVE=1`, не называть это прогоном Docker CI.
- Browser-регрессия устанавливает MutationObserver до выполнения приложения и сохраняет
  даже краткие error SVG/сообщения; отдельно проверяет успешную конечную отрисовку.
  Проверить чувствительность наблюдателя намеренным кратким маркером ошибки в тестовом
  сценарии, не добавляя сломанные схемы в публикуемые страницы.
- Пройти все 44 схемы с прокруткой до lazy-блоков. Проверить увеличение/уменьшение,
  сброс, перемещение и fullscreen/выход на flowchart и sequence. Кнопки доступны
  клавиатурой и имеют понятные доступные имена; темы переключаются без ошибок.
- Проверить прямую загрузку, настоящий reload, SPA и Back, включая проблемный
  `caching-strategies#networkonly` и якоря ниже схем. Светлая/тёмная тема сохраняется
  через `vitepress-theme-appearance`, фактическая тема проверяется после reload.
  На 2560×1440 и 390×844 проверить начальный FullWidth и сохранённый узкий режим.
- Для корня и вложенного `SITE_BASE` использовать соответствующие отдельные сборки.
  Целевой заголовок после отрисовки виден ниже шапки, отсутствует горизонтальный
  overflow страницы; пользовательский ввод отменяет отложенную коррекцию прокрутки.
  Замеры начального layout и стабильного положения сохраняются раздельно.
- Результат — проверенная отдельная ветка и PR с превью; проверить CI и реальную
  публикацию превью. Слияние отдельно не поручено.

Ошибки схем не скрываем CSS или подавлением ошибок. Если renderer не проходит эту
приёмку, зафиксировать конкретную причину и пересмотреть интеграцию; сам факт замены
пакета не доказывает исправление гонки или всех скачков страницы.
