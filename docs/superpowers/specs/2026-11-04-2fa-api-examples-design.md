# Читаемость документации 2FA и примеры API

Дата: 04.11.2026. Статус: предложено к согласованию.
Дополнение к `2026-11-03-2fa-documentation-design.md` по замечаниям владельца.

## Цель

Расшифровать TOTP, исправить разрыв заголовка таблицы и дать компактные примеры
входных и выходных данных непосредственно в строках согласованных операций API.
Требования описываются прямо, без истории их обсуждения.

## Проверенные факты

- В обзоре TOTP сейчас не расшифрован.
- Общее правило `.vp-doc th, .vp-doc td { overflow-wrap: anywhere; }` допускает разрыв
  слова «Авторизация»; проблема видна на предоставленном скриншоте.
- В таблице перечислены четыре операции: `POST /auth/enable2fa`, `/auth/confirm2fa`,
  `/auth/login`, `/auth/disable2fa`.
- Прочитанный backend#23 задаёт JSON настройки и поля ответа входа. Для подтверждения
  и отключения указан `200 OK`, тело успешного ответа не определено.
- На трёх страницах есть историческая оговорка «По уточнению от 04.11.2026».

## Рассмотренные варианты

1. Примеры отдельными блоками под таблицей: больше места для JSON, но информация
   одной операции разделена между таблицей и нижними блоками.
2. Компактный JSON в ячейках: вход и выход видны в строке операции; для длинных
   значений нужны сокращённые демонстрационные данные и проверка узкого экрана.

Владелец выбрал второй вариант: небольшой JSON внутри ячеек с сокращением длинных значений.

## Изменения

- При первом упоминании в обзоре: TOTP — Time-based One-Time Password,
  одноразовый пароль на основе времени. Остаётся пояснение про шестизначный код.
- Столбец «Авторизация» получает достаточную ширину; заголовок не разбивается внутри
  слова. Оформление ограничено таблицей операций 2FA, остальные таблицы не меняются.
- На трёх страницах используется прямая формулировка:
  «Ограничения попыток ввода TOTP-кода и пароля не требуются».
  История уточнения и пояснение «соответствующее требование backend#23 не применяется» удаляются.
- В ячейках входа и успешного результата каждой операции размещаются компактные
  многострочные JSON-примеры, когда соответствующее тело задано контрактом.
  Пояснения к параметрам, авторизации, результатам и статусам сохраняются.
- Для подготовки настройки явно указано отсутствие тела запроса. Для подтверждения
  и отключения показаны `200 OK` и оговорка, что тело ответа в контракте не задано;
  пустой объект или новые поля не придумываются.
- Для входа показан пример с включённой 2FA; сохранено описание входа без второго
  фактора. Пример ответа содержит все семь согласованных полей пользователя.
- Данные примеров вымышленные. Длинная строка PNG data URI показана с многоточием
  внутри строки; рядом поясняется, что значение сокращено. Сокращение не скрывает
  имена полей, типы, структуру JSON, ведущие нули кода и значения `has_2fa`.
- Малый размер блоков достигается компактными отступами и читаемым шрифтом.
  На узком экране допустима горизонтальная прокрутка самой таблицы, но не страницы.

## Границы и проверка

JSON-примеры контрактов теперь явно разрешены вместо прежней оговорки, что они не нужны.
Реализация обработчиков, новые поля API, библиотеки, изменения GitHub issues, frontmatter
и схемы не входят в правку. Способ встраивания JSON выбирает исполнитель среди имеющихся
в проекте возможностей без новых зависимостей.

Проверить JSON-примеры, сохранность контрактов, сборку сайта и отсутствие разрыва
«Авторизация». В браузере проверить таблицу и примеры на 390 и 1440 px, в светлой
и тёмной темах: содержимое доступно, длинные значения сокращены явно, страница не переполняется.
Использовать обязательные проверки репозитория; не добавлять тесты, зеркалирующие текст.
