# Ширина чтения до первого отображения страницы

## Цель

При прямом открытии и hard reload страница сразу появляется с нужной шириной.
Текст, шапка и левое меню не перемещаются из стандартной узкой раскладки
в выбранную читателем. Это небольшое исправление интеграции Enhanced Readabilities.

## Проверенные факты

- База исследования: docs `5c14f0c`; VitePress `2.0.0-alpha.21`,
  `@nolebase/vitepress-plugin-enhanced-readabilities` `2.21.1`.
- На записи владельца `bandicam 2026-11-04 01-17-41-239.mp4` открыта страница
  `/branches/docs-2fa-module2/modules/2/tracks/2fa`: при загрузке меняются ширина
  текста и положение навигации.
- В `theme/index.ts` задан FullWidth по умолчанию и отключены анимации.
  В установленном `LayoutSwitch.vue` класс раскладки добавляется на `body`
  после mounted. Ползунки ширины устанавливают CSS-переменные через debounce 1000 мс.
  Отключение анимации эти задержки не устраняет.
- Измерение страницы из записи в Chrome, 2560×1280, без кеша: первый показ
  около 728 мс; ширина текста 688 → 1904 px при применении FullWidth около
  1000 мс. Для сохранённого режима BothWidthAdjustable обнаружены два изменения:
  применение режима, затем сохранённых процентов. В сохранённом Original
  ширина оставалась неизменной. HTTP 200, Mermaid на странице отсутствует.
- Трассировка и диагностический скрипт сохранены локально в основном checkout:
  `.superpowers/diagnostics/2026-11-04-reading-width/{probe.ts,trace.json}`.
  Время зависит от загрузки; критерий исправления — геометрия видимых кадров.
- В `config.mts` уже есть ранний head-скрипт загрузчика статьи.
  `article-loading.ts` и его CSS скрывают статью только при наличии Mermaid;
  шапка и боковое меню остаются видимыми.

## Подходы

1. **Ранняя установка раскладки — выбран владельцем.** До первого отображения
   применить режим и проценты из существующих настроек плагина. Это устраняет
   позднее изменение ширины без дополнительного ожидания. Интеграция зависит
   от классов и CSS-переменных установленной версии; это покрывается проверкой.
2. **Общий загрузчик до готовности ширины.** Можно скрыть промежуточную раскладку,
   но понадобится закрыть также шапку и меню, а обычные статьи начнут ждать
   запуск приложения и отложенное применение процентов.

Выбран первый подход. Форк разрешён владельцем при необходимости, но начальное
решение — локальная интеграция с установленным пакетом. Если она потребует
существенного дублирования плагина, выбор механизма нужно пересмотреть.

## Поведение и границы

- Без сохранённого выбора сразу действует FullWidth. Сохранённые Original,
  FullWidth и оба регулируемых режима сохраняют смысл и настройки читателя.
- Для регулируемых режимов нужные проценты применяются вместе с режимом,
  с теми же пределами и правилами адаптивности, что у плагина. Его последующая
  инициализация не должна менять уже показанную геометрию.
- Недопустимые значения и недоступный localStorage не ломают страницу:
  применяется согласованный безопасный вариант. Валидные настройки не сбрасываются;
  ошибочные значения не должны вызвать поздний переход в другую раскладку.
- Меню плагина продолжает менять и сохранять ширину; переходы по сайту,
  возврат на страницу и изменение размера окна работают как раньше.
- Исправление охватывает основные страницы и branch preview с вложенным base.
  Учитываются обе темы и мобильная раскладка. Без JavaScript текст доступен.
- Новый общий загрузчик, новые зависимости и изменение дизайна не требуются.
  Текущий загрузчик Mermaid и коррекция якорей сохраняют своё назначение.
  Исправление не обещает устранить сдвиги от любых поздно загружаемых ресурсов.

## Проверка и решения исполнителя

Расширить существующие браузерные проверки чтения: с начала документа наблюдать
геометрию статьи, меню и шапки, отдельно учитывать момент первого отображения.
Проверить fresh/hard reload без настройки, все четыре режима, сохранённые
проценты и запуск с задержанным JS. Конечная правильная ширина сама по себе
не доказывает отсутствие скачка. После запуска приложения и его отложенных
обновлений видимая раскладка должна оставаться выбранной с первого показа.

Дополнительно проверить недоступное/испорченное хранилище, мобильный viewport,
возврат desktop после resize, смену режима через меню, вложенный base и страницу
с Mermaid и прямым якорем. Выполнить обязательные проверки репозитория.

Исполнителю остаётся выбрать минимальное место раннего применения состояния
и способ согласовать его с плагином без конкурирующих постоянных обработчиков.
Проверки должны подтвердить работу на собранном сайте; до этого исправление
не считается доказанным.
