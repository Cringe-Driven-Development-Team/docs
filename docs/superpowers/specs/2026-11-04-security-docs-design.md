# Безопасность: актуальные CSRF и XSS

Статус: согласовано пользователем 04.11.2026. Работа в репозитории docs, ветка `docs/security-docs`.

## Цель и границы

Раздел документации работающего продукта должен объяснять текущую защиту сервиса.
Он служит каноническим источником для OpenWiki и агентов. Историческое описание CSRF
до BFF удаляется целиком: оно не остаётся ни архивом, ни альтернативным описанием защиты.
Основной текст объясняет механизмы и их ограничения, без истории миграции и хронологии проверок.

Меняем страницы документации, навигацию, ссылки, переадресации и связанные проверки.
Код приложения, инфраструктуру, зависимости и планы учебных модулей не перерабатываем.
OpenWiki вручную не редактируем и в рамках этой задачи не перегенерируем:
её отдельное обновление выполняется по явной команде владельца.

## Рассмотренные подходы

1. Сохранить старые страницы по прежним адресам и связать с новым разделом — отклонено пользователем:
   документация должна описывать фактический прод, а не историю.
2. Перенести старые страницы в архив внутри «Безопасности» — отклонено по той же причине.
3. Удалить старый раздел и создать актуальные страницы CSRF/XSS — выбран пользователем.
   Прежние опубликованные адреса получают переадресации, без сохранения старого содержания.

## Структура и содержание

Согласовано пользователем: все новые страницы находятся под `/documentation/security/`.
Исходники — `site/documentation/security/index.md`, `csrf.md`, `xss.md`, `csp.md`.

| Страница | Путь | Содержание |
| --- | --- | --- |
| Безопасность | `/documentation/security/` | Кратко: ответственность браузера, BFF и Go; ссылки на три подраздела |
| CSRF | `/documentation/security/csrf` | Угроза; браузерная cookie сессии; проверки BFF; почему заголовок не секретный токен; граница BFF → Go; отказы и ограничения |
| XSS | `/documentation/security/xss` | Угроза; данные в bootstrap; текстовые узлы в интерфейсе; ответственность Go; ограничения HTML/URL и установленной версии рендерера |
| CSP | `/documentation/security/csp` | Заголовок страницы и только `TODO` |

В меню «Безопасность» заменяет старый CSRF и содержит детей CSRF, XSS, CSP.
Обзор не дублируется дочерним пунктом. Главная документации получает краткое актуальное
резюме со ссылкой на раздел. На странице BFF удаляется описание сохранённой истории CSRF,
а объяснение защиты связывается с канонической страницей CSRF. Полный пересмотр документации
всех возможностей BFF не входит в эту задачу.

Удаляются `site/documentation/csrf/index.md`, `scenarios.md`, `checks.md`.
Их опубликованные адреса перенаправляются на новый CSRF; существующие переадресации
`/security/csrf/`, `/security/csrf/scenarios`, `/security/csrf/checks` также направляются
сразу на новую страницу. Все актуальные внутренние ссылки обновляются.
Старые якоря, относящиеся только к удалённой модели, не становятся разделами нового документа.

Проверка через Obscura: 04.11.2026 около 01:17 МСК (03.11, 22:17 UTC).
Гость попадает на `/login`, bootstrap содержит `user: null`.
GET `users.me` без `X-CSRF` дал `403 csrf_invalid`, с заголовком — `401`.
POST `auth.login` с пустым JSON без заголовка дал `403 csrf_invalid`, с ним — `400`
с ошибками полей. Старый GET `/api/v1/users/me` дал `404`.

Локально на указанном frontend SHA прошли 7 существующих тестов CSRF/сериализации bootstrap:
`bun test --preload ./apps/bff/test/setup.ts apps/bff/test/bff.test.ts --test-name-pattern 'CSRF:|строки пользователя'`.
Авторизованные XSS-сценарии на проде, чужой Origin в браузере и совпадение работающих
backend/infra с прочитанными SHA пока не подтверждены. В документации нельзя подменять
эти свидетельства чтением main. Перед утверждениями о полном сценарии нужны дополнительные
проверки; при их отсутствии граница остаётся явно обозначенной.

## Правила изложения и приёмка

Основной текст отвечает «как защищён текущий сервис». Источники на SHA и краткая область
проверки идут в конце соответствующей страницы, без дневника проверок. Существенные
ограничения остаются видимыми рядом с механизмом: HttpOnly не мешает XSS выполнять запросы
из страницы; текстовый вывод не означает безопасность произвольных HTML/URL.

Критерии: старого описания CSRF нет в страницах, меню и поисковом индексе сайта;
новые страницы и ссылки доступны; CSP содержит только TODO; старые адреса открывают новый CSRF;
текст не обещает непроверенную защиту. Старую generated OpenWiki это изменение само не обновляет.

Проверки реализации: `bun run typecheck`, `bun run test`, `bun run build`;
тесты страниц/ссылок/redirects актуализированы, собранные страницы и навигация проверены
через существующий browser CLI. Для переадресаций проверяются корневая и вложенная база.

Дополнение согласовано пользователем: две содержательные Mermaid, без Eraser.
В CSRF — ветвление проверок BFF с отказом до Go; в XSS — безопасное встраивание
bootstrap и последующий текстовый вывод, с отдельным входом JSON из RPC.
Каждая схема встроена в свою страницу рядом с объяснением через DiagramSection.
Новые зависимости не требуются. Точную редактуру, названия внутренних
заголовков и группировку источников определяет исполнитель в указанных границах.
