# Точечное обновление docs-site для текущего сайта

## Цель и проверенные факты

Пользователь подтвердил четыре дополнения к `docs-site` и явно выбрал SDD. Это обновление справочных инструкций; поведение сайта уже реализовано. `docs-modules` соответствует установленному module-graph и не меняется.

Проверенная база — `437f8fd308bf54eb1386d76465c7fab2d56874c6`. В `package.json` установлен VitePress `2.0.0-alpha.21`; точные версии читаются из проекта, отдельная таблица зависимостей в скилле не нужна. Репозиторный источник — `.agents/skills/docs-site/SKILL.md`; `bun run skills:sync` создаёт побайтовую копию `.claude/skills/docs-site/SKILL.md`, но не обновляет домашний каталог Codex.

## Содержание дополнения

1. Страницы документации располагаются под `site/documentation/`, включая реальные вложенные маршруты. Ссылки добавляются в существующую `documentationSidebar` для ключа `/documentation/` в `site/.vitepress/config.mts`; дочерние страницы — через `items` общего дерева. Родитель может иметь `link`, `collapsed` и `items`; обзор не надо дублировать ребёнком. Меню модулей строится через `moduleSidebar(modules)` отдельно. `aside` управляет правым оглавлением, а не левой навигацией. При переносе опубликованного адреса действует существующий раздел про redirects.
2. Enhanced Readabilities настроен в `site/.vitepress/theme/index.ts`: `LayoutMode.FullWidth` — начальное значение, выбор читателя сохраняется и имеет приоритет. CSS-правки проверяются с чистым хранилищем и сохранённым узким режимом, на мобильной и настольной ширине. Настройки чтения, ширина и Mermaid-прокрутка сохраняют работу; обычная текстовая правка не требует перенастройки темы.
3. Inline Link Preview подключён Markdown-transform и компонентом `DocLinkPreview`. Политика находится в `site/.vitepress/link-preview.ts`, `canPreviewDocLink`: текстовые документы того же origin внутри текущего SITE_BASE допустимы; текущая страница/её якорь, внешние ссылки, файлы, OpenWiki, корневая архитектура (старый и новый namespace) и графы модулей исключены. Подстраница `modules/2/tracks/offline/architecture` — обычный документ и допустима. Полный переход в OpenWiki сохраняется через native `target="_self"`; относительный raw href при переносе страницы пересчитывается, base к raw HTML автоматически не добавляется.
4. Для изменений навигации/темы/Markdown-виджетов описать существующий browser CLI: после подходящей собранной `dist` запускать `CHROMIUM_PATH="/path/to/chrome" bun scripts/check-readability.ts hierarchy scroll` (подставить установленный Chrome и подходящие секции). Секции: `hierarchy` — дерево/вложенные маршруты/старые ссылки/поиск; `scroll` — якоря после Mermaid и сохранённые ширины; `pages` — отображение страниц и Mermaid; `plugins` — ширина, Tabs/клавиатура, Group Icons, preview и граф; `title` — видимость бренда. Можно выбрать несколько секций; без аргументов выполняются все. Подбирать проверки к изменению, не требовать полный прогон при каждой правке текста. Для base-зависимых изменений собрать и проверить корень и вложенную базу с одним и тем же SITE_BASE; смена env у готового dist не пересобирает URL. `READABILITY_ARTIFACTS_DIR` — необязательный каталог результатов. Проверять собранный HTML, не Vite dev с fallback для generated iframe.

## Global Constraints

- Меняются только `.agents/skills/docs-site/SKILL.md`, его зеркало `.claude/skills/docs-site/SKILL.md` и документы этой задачи; `docs-modules`, сайт, зависимости, схемы и OpenWiki не меняются.
- Сохраняются имя, смысл description, остальные поля frontmatter, правила редактуры, проверенных фактов, истории, ссылок и redirects; в description убираются только угловые скобки у `<Diagram>` для прохождения валидатора; добавление остаётся кратким справочником по текущим исходникам, без нового универсального процесса или запретов.
- Копия Claude создаётся через `bun run skills:sync`; проверенная установленная копия `/home/oleg/.codex/skills/docs-site/SKILL.md` обновляется после ревью с проверкой исходного хеша, без перезаписи параллельных правок.
- Проверки соразмерны изменению: retrieval/application-сценарий до/после, валидатор скилла, тесты синхронизации и обязательные проверки репозитория; новые тесты на наличие конкретных фраз и повторная UI-матрица не нужны.
- Результат — коммит в feature-ветке, draft PR и установленная проверенная копия; слияние нового PR отдельно не поручено.

## Приёмка

Свежий агент находит в скилле четыре нужные группы сведений и применяет их к новой вложенной странице, сохранённой ширине, ссылкам разных типов и выбору browser-секций. Ответ сверяется с исходниками, а не с совпадением формулировок. Скилл остаётся согласован с текущим кодом; зеркала побайтово равны, installed Codex равен принятому исходнику после установки. В отчёте честно указаны проверки и ограничения.
