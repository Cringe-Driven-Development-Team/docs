## Задача и выбранный подход

Добавить общий `FigmaEmbed.vue` на основе официального Figma Embed. Первое применение —
раздел «Подключение» страницы `site/modules/2/tracks/2fa-front.md` из ветки
`docs/2fa-module2`. Читатель видит нужный экран рядом с описанием сценария и может
самостоятельно исследовать остальные макеты страницы Release внутри iframe.

Рассмотрены три подхода: iframe непосредственно в Markdown (минимум кода, но повторяется
оформление), общий Vue-компонент (единое оформление и короткая запись на страницах),
Markdown-плагин (добавляет зависимость и требует настройки Figma). Пользователь выбрал
официальный Embed и общий Vue-компонент. Переключатели состояний в документации не нужны.

## Поведение

В разделе «Подключение» добавить один виджет после существующего `DiagramSection`,
перед разделом «Вход». Это предложение по размещению: полная ширина статьи оставляет
достаточно места макету и сохраняет связь текста с Mermaid.

Начальный фокус — QR-фрейм `496:16027`, без требования охватывать внешние подписи
или заголовок секции. Это выбор стартового узла, а не обрезка картинки и не запрет
перемещаться: дальше читатель может исследовать всю Release, в том числе соседние подписи.
Файл Figma и его настройки доступа не изменяются.

Оставить штатные средства перемещения, масштаба и fullscreen Figma. Под iframe —
обычная ссылка «Открыть в Figma» на тот же экран. Все существующие ссылки на макеты
и описание целевого, а не подтверждённого на проде поведения 2FA сохраняются.

## Компонент и оформление

Предлагаемый авторский интерфейс: `FigmaEmbed` с обязательными `url` и `title`.
`url` — обычная HTTPS design-ссылка Figma на нужный узел; из неё компонент формирует
официальный embed URL, оставляя file key и node-id и добавляя `embed-host`.
Параметры Dev Mode (`m=dev`) не переносятся. Принимаются только поддержанные Figma
design URL; произвольные адреса и схемы не становятся iframe. Неподдержанный URL
даёт явную ошибку при сборке, а не незаметно пустой виджет.

Компонент регистрируется в существующем `enhanceApp` для повторного использования.
Iframe имеет содержательный `title`, `loading="lazy"`, разрешение fullscreen и
ширину 100%. Предлагаемая единая высота — 600 px; её удобство проверяется на мобильной
и настольной ширине. Рамка и ссылка используют существующие токены темы VitePress.
Новые пакеты, собственные zoom-панели и слой поверх iframe не нужны.

Визуальные ориентиры: последний скриншот пользователя определяет стартовый экран;
существующая тема документации — внешнее оформление; официальный Figma Embed —
управление внутри виджета. Декоративные элементы и новый визуальный стиль не добавляются.

## Границы и проверка

Эта итерация включает компонент, регистрацию, оформление, одно встраивание подключения
2FA и проверки. Прототипы `/proto/`, галереи, выбор состояний, экспорт картинок и
автоматическое встраивание остальных макетов в неё не входят.

Проверить преобразование URL (включая удаление Dev Mode и отклонение чужого адреса),
успешную SSR-сборку, размещение виджета и сохранность якоря «Подключение». В браузере
проверить первый QR-экран, свободное перемещение по Release, zoom/fullscreen, ссылку,
отсутствие горизонтального переполнения на телефоне и работу во вложенной базе превью.
Отсутствие ошибки сборки не считается проверкой доступности Figma.

Перед коммитом выполнить проверки репозитория: `bun run modules:check`,
`bun run typecheck`, `bun run test`, `bun run build`; браузерные проверки подбирать
к изменению по `docs-site`. Существующую работу в ветке `docs/2fa-module2` сохранить;
спецификация подготовлена в отдельном worktree на её актуальной базе.

Встроенный просмотр сохраняет [права доступа Figma](https://developers.figma.com/docs/embeds/security-access/).
Доступ анонимного читателя и реальный стартовый viewport ещё не проверены. Макеты живые:
их содержимое может измениться без пересборки документации. Обычная ссылка остаётся
доступна независимо от загрузки iframe.
