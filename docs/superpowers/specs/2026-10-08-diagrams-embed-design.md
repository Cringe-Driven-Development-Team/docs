# Схемы внутри VitePress: раздел «Архитектура» — дизайн

Дата: 2026-10-08. Статус: дизайн утверждён в чате, ждёт ревью спеки.

## 1. Цель

Схемы Eraser сейчас открываются с отдельной белой страницы `/docs/diagrams/` вне VitePress. Их нужно
встроить в сайт, как макеты Figma встраиваются в Confluence: страница «Архитектура» в меню VitePress,
на ней схемы MVP живыми карточками с масштабом и перетаскиванием, рядом — текст. Карточку можно
вставить и на любую другую страницу.

Успех: пункт меню «Архитектура» открывает `/architecture/` внутри VitePress; шесть схем MVP читаются
на странице (масштаб в рамке, полный экран); старые адреса схем и якоря индекса ведут в новые места;
`check-site` и тест-страж зелёные.

## 2. Проверенные факты

Репа `docs`, `main` на `07fb9bd`:

- `scripts/build-index.ts`: `ROOT_TAB = "mvp"`, `HIDDEN_FOLDERS = ["bff", "frozen-k3s"]` —
  `indexNames` убирает их схемы, на индексе только схемы корня; `renderIndex(names, { previewsHref,
  sizes, assetPrefix })` пишет `INDEX_FILE = dist/diagrams/index.html` (карточки `#<имя>`, PNG,
  ссылки HTML · PNG, табы, ссылка «Превью веток»); `pngSize(path)` читает размер PNG из заголовка.
- `scripts/build-site.ts:250-253`: после превью веток перезаписывает `INDEX_FILE` индексом с
  `previewsHref: "../branches/"`; превью веток — `dist/branches/<slug>/`, их список —
  `dist/branches/index.html`.
- `scripts/build-vitepress.ts`: `protectedFiles(diagrams)` — `<имя>.html`, `<имя>.png` и
  `diagrams/index.html`; перенос сайта VitePress в `dist/` падает на совпадении с ними.
- `scripts/check-site.ts:65-77`: проверяет `<a href>`, `<link href>`, `<script src>`, `<img src>`;
  `<iframe src>` не проверяет; страницы схем пропускает (`htmlPages`).
- `site/.vitepress/site.ts`: `diagramsRedirect(hash, base)` — главная с якорем `#ci` или `#bff/ci`
  переводит на `diagrams/<якорь>`; вызывается из `site/.vitepress/theme/index.ts:45`.
- `site/.vitepress/config.mts`: nav «Архитектура» → `/diagrams/` с `target: '_self'`;
  `site/index.md` — кнопка и карточка «Схемы архитектуры» → `/diagrams/`, `target: _self`.
- `package.json`: `build:native` = `… render:native → index → mermaid → site:vitepress → site:check`:
  PNG и HTML схем есть в `dist/` до сборки VitePress.
- Схемы MVP в `dist/`: HTML от Eraser — самодостаточный холст фиксированного размера (корневой
  `div` `position: relative; width: Npx; height: Npx`), шрифты в data URI, скриптов нет, около 750 КБ;
  PNG вдвое больше холста (`deployment` 1636×732 и PNG 3272×1464, `ci` 1872×1132 и 3744×2264,
  `contract` 2732×912 и 5464×1824).
- README, таблица «MVP (`diagrams/`)» — описание каждой из шести схем; правило «добавил файл — добавь
  строку».
- Замороженные схемы рендерятся в `dist/bff/*.html` и `dist/frozen-k3s/*.html`; раздел VitePress
  `site/bff/` выдаёт `dist/bff/{index,contract,auth}.html` — общий путь `/docs/bff/`.

Внешние:

- `@panzoom/panzoom` 4.6.2, MIT, npm: масштаб и сдвиг элемента, колесо, щипок.
- Fullscreen API: на iPhone Safari `requestFullscreen` для элементов, кроме `video`, недоступен.

## 3. Решения

| Решение | Почему | Отвергнуто |
| --- | --- | --- |
| Раздел «Архитектура» в VitePress вместо белого индекса | один сайт, текст рядом со схемой, ссылки на схему из других страниц | оставить индекс и добавить только компонент |
| Карточка — iframe с HTML схемы в натуральную величину, масштаб обёртки через `@panzoom/panzoom` | схемы не пересобираются, стили Eraser изолированы, текст чёткий при любом масштабе | DOM схемы в Shadow DOM (`@font-face` в shadow root Chrome игнорирует); PNG с масштабом (мылится, текст не выделяется) |
| Масштаб как у Figma в Confluence: Ctrl/⌘ + колесо и щипок, колесо без модификатора листает страницу | не перехватывать прокрутку страницы | масштаб колесом всегда; только полноэкранный просмотр |
| Страница `/architecture/`, не `/bff/…` | путь `/docs/bff/` уже делят раздел VitePress и замороженные схемы | страницы схем в корне |
| `bff/` и `frozen-k3s/` в меню не появляются | сейчас скрыты с индекса (`HIDDEN_FOLDERS`), заморожены | отдельные страницы заморозок |
| Натуральный размер холста — PNG / 2 | PNG рендерится с масштабом 2 (§2), размер PNG уже читает `pngSize` | разбор HTML схемы |
| Тест-страж «каждая схема корня встроена на `/architecture/`» | заменяет автоматическую сборку индекса: новая схема не потеряется | ручная проверка |

## 4. Устройство

### 4.1. Компонент `Diagram`

- `site/.vitepress/theme/Diagram.vue`, регистрируется глобально в теме; в markdown:
  `<Diagram name="deployment" />`, `name` — имя схемы как в `diagrams/` (`deployment`, `bff/ci`).
- Размеры — из загрузчика данных VitePress `site/.vitepress/theme/diagrams.data.ts`: на сборке читает
  `dist/<имя>.png` через `pngSize`, отдаёт `{ [имя]: { width, height } }` — PNG / 2, округлённо. Нет
  PNG (например, `site:dev` без рендера) — `{ width: 1600, height: 900 }`, карточка показывает
  «Схема не отрисована: `bun run render`».
- Разметка карточки: заголовок не рисует (заголовок даёт markdown); рамка с фиксированной высотой
  `min(70vh, натуральная высота × масштаб «вписать»)`; внутри обёртка размером с холст, в ней
  `<iframe src="<base><имя>.html" width height loading="lazy" sandbox="" title="Схема <имя>">`; поверх
  iframe прозрачный слой — ловит указатель, иначе события уходят во фрейм. Панель над рамкой:
  «−», «+», «Вписать», «На весь экран»; под рамкой — ссылки «HTML» и «PNG» на `<base><имя>.html`/`.png`.
- Масштаб: при монтировании и смене ширины рамки — «вписать» (масштаб = ширина рамки / ширина холста,
  не больше 1); диапазон от «вписать» до 4; шаг кнопок 1,25. Колесо с Ctrl или ⌘ и щипок — масштаб к
  точке указателя; колесо без модификатора не перехватывается. Перетаскивание мышью и одним пальцем.
- Полный экран: `requestFullscreen` у рамки; если недоступен (iPhone) — та же рамка как
  `position: fixed; inset: 0` поверх страницы, `Esc` и кнопка закрывают. В полном экране — снова
  «вписать».
- Оформление: рамка в цветах темы VitePress (`--vp-c-divider`, `--vp-c-bg-soft`), холст схемы остаётся
  белым в обеих темах. Кнопки — `<button>` с `aria-label`, видимый фокус.

### 4.2. Страница `/architecture/`

- `site/architecture/index.md`, заголовок «Архитектура: MVP», `aside: false` (колонка «На этой
  странице» отключена, схема шире).
- Шесть разделов `## deployment`, `## ci`, `## cd`, `## frontend`, `## contract`, `## infra` (якорь =
  имя схемы), в каждом — описание из таблицы README (одно-два предложения) и `<Diagram name="…" />`.
- Вверху — строка про замороженные варианты: ссылки на HTML схем `bff/` и `frozen-k3s/` списком.
- nav: «Архитектура» → `/architecture/`, `activeMatch: '^/architecture/'`, без `target`. Главная:
  кнопка и карточка → `/architecture/`, без `target`.
- «Превью веток» — пункт nav `{ text: 'Превью веток', link: '/branches/', target: '_self' }` только
  при `SITE_BASE === '/docs/'` (сборка `main`); в превью ветки пункта нет.

### 4.3. Старые адреса

- `/docs/<имя>.html` и `.png` не меняются.
- `dist/diagrams/index.html` — страница-переадресация (вместо индекса): скрипт читает `location.hash`;
  `#<имя схемы корня>` → `../architecture/#<имя>`; `#<папка>/<имя>` скрытой папки → `../<папка>/<имя>.html`;
  пустой или неизвестный — `../architecture/`. Без скрипта — ссылка «Схемы переехали» на
  `../architecture/`. `noindex`.
- Главная с якорем (`diagramsRedirect`): `#<имя>` → `architecture/#<имя>`, `#<папка>/<имя>` →
  `<папка>/<имя>.html`.
- `build-site.ts` больше не перезаписывает `INDEX_FILE` индексом с превью — пишет ту же переадресацию;
  список превью `dist/branches/index.html` не меняется.

### 4.4. Сборка и проверки

- `scripts/build-index.ts`: `renderIndex` заменяется на `renderRedirect(names)`; `indexNames`,
  `HIDDEN_FOLDERS`, `pngSize`, `pngSizes` остаются (их зовут переадресация и загрузчик данных);
  табы, карточки и стили индекса удаляются. Тесты `build-index.test.ts` переписываются под
  переадресацию.
- `scripts/check-site.ts`: `<iframe src>` — ссылка, должна существовать. Ссылки в `branches/` не
  проверяются: список превью появляется только на Pages после `build-site.ts`, а пункт «Превью веток»
  есть в сборке `main`.
- `protectedFiles` не меняется (`diagrams/index.html` по-прежнему пишет `index`).
- Тест-страж `scripts/architecture-page.test.ts`: каждая схема из `indexNames(diagramNames())`
  встречается на `site/architecture/index.md` как `<Diagram name="<имя>"` и как заголовок `## <имя>`.
- Тест размера: для каждой схемы корня ширина и высота корневого `div` в `dist/<имя>.html` равны
  PNG / 2 — проверка запускается, только если `dist/` собран (иначе `test.skip` с причиной).
- `package.json`: `@panzoom/panzoom` `4.6.2` в devDependencies из публичного npm.

### 4.5. Документация

- README: абзац про индекс заменяется на «Схемы MVP — на странице `/docs/architecture/`; добавил схему
  в `diagrams/` — добавь строку в таблицу и раздел с `<Diagram>` на `site/architecture/index.md`
  (тест-страж)». CLAUDE.md, «Схемы»: то же правило одной строкой.

## 5. Проверка

- `bun run typecheck && bun run test && DIAGRAMS_NATIVE=1 bun run build` зелёные; `site:check` видит
  `/architecture/` и iframe.
- В браузере на локальном сервере `dist/` под `/docs/`: меню «Архитектура» без полной перезагрузки;
  шесть схем вписаны; `−`/`+`/«Вписать», Ctrl/⌘ + колесо к указателю, колесо без модификатора листает
  страницу, перетаскивание; полный экран и выход по `Esc`; 375 px с эмуляцией касаний — щипок,
  перетаскивание, псевдополноэкранный режим; тёмная тема; `/docs/diagrams/#ci`,
  `/docs/diagrams/#bff/ci`, `/docs/#ci`, `/docs/diagrams/` переадресуют по §4.3.
- Превью ветки собирается со своим `SITE_BASE`, iframe грузит схему ветки.

## 6. Не входит

- Показ замороженных `bff/` и `frozen-k3s/` в меню и их страницы.
- Правки самих схем и пайплайна рендера.
- Тёмная тема для холста схем.
- Встраивание схем в страницы BFF и CSRF — компонент это позволяет, но отдельной правкой.
