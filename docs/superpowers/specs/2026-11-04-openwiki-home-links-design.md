# Переход в OpenWiki с главной

Статус: подход и спецификация согласованы пользователем 04.11.2026.

## Цель

Кнопка OpenWiki и карточка «Найти сведения» на главной открывают визуализатор
в текущей вкладке без страницы 404 VitePress. Адрес остаётся `/openwiki/`
с учётом базы сайта, в том числе в превью ветки.

## Проверенные факты

Проверка 04.11.2026, исходники docs на
`5c14f0c9686672d3771f59be31480cacb7d54824`:

- В записи пользователя на 00:03 виден визуализатор, на 00:05 — 404 VitePress
  по тому же адресу `/openwiki/`.
- Прямой HTTP-запрос к `https://docs.cellestial.ru/openwiki/` вернул 200
  и HTML с заголовком `OpenWiki visualizer`.
- В опубликованном HTML главной три ссылки на `/openwiki/`. Только ссылка
  верхнего меню имеет `target="_self"`; у кнопки и карточки атрибут отсутствует.
- `site/index.md` задаёт обе ссылки через frontmatter. В
  `site/.vitepress/config.mts` ссылка меню уже содержит `target: '_self'`.
- Установленный VitePress 2.0.0-alpha.21 передаёт `action.target` и
  `feature.target` в ссылки. Его `getRoutableLinkUrl` в
  `node_modules/vitepress/dist/client/app/router.js` исключает из клиентской
  навигации ссылки с явно заданным `target`.
- `scripts/export-openwiki.ts` публикует отдельный HTML-визуализатор в
  `dist/openwiki`; это не маршрут страницы VitePress.

Причина: клиентский роутер VitePress перехватывает обе ссылки главной,
хотя для визуализатора нужен полный переход браузера.

## Рассмотренные подходы

1. **Выбран:** добавить `target: _self` обеим ссылкам в `site/index.md`.
   Повторяет существующее решение верхнего меню, сохраняет текущую вкладку
   и штатную подстановку базы VitePress. Цена — полная загрузка отдельной страницы,
   необходимая для запуска визуализатора.
2. Перехватывать переходы в коде темы. Позволяет централизованно обработать
   адрес, но добавляет обработчик и логику маршрутизации для двух декларативных
   ссылок. Избыточно для этой ошибки, не выбрано.

## Изменение и границы

Продуктовая правка — два поля `target: _self` в `site/index.md`.
Используются существующие компоненты VitePress, внешний вид сохраняется.
Новые зависимости, маршруты, редиректы и генерация wiki не нужны.
Ссылка верхнего меню служит контрольным рабочим примером.

## Проверка и приёмка

- Проверить итоговые ссылки главной: у кнопки и карточки правильный `href`
  и `target="_self"`.
- В браузере на собранном сайте независимо кликнуть кнопку и карточку:
  открывается визуализатор в той же вкладке, без 404 VitePress.
- Повторить для корня сайта и вложенной базы превью; переход сохраняет базу.
- Проверить возврат Back на главную и прямую перезагрузку визуализатора.
- Перед коммитом выполнить обязательные проверки репозитория:
  `bun run modules:check`, `bun run typecheck`, `bun run test`, `bun run build`.

Способ браузерной проверки и место минимальной проверки регрессии определяются
в плане реализации по существующим инструментам. Реализация начинается после
согласования спецификации, подготовки плана и выбора пользователем способа
его выполнения.

## Дополнение: фон шапки при прокрутке

Пользователь дополнительно поручил исправить просвечивание схемы под поиском,
показанное на снимке и записи от 04.11.2026 16:59 (00:02–00:05).
Сохраняется текущий способ выполнения `executing-plans`.

Проверенные факты: на странице `modules/2/tracks/bff/auth`, ширина 2560 px,
режим Nolebase FullWidth, боковая панель заканчивается на 272 px,
а фон `VPNavBar::before` начинается с 832 px. VitePress вычисляет отступ
по своей стандартной максимальной ширине, Nolebase расширяет страницу.
Сам `VPNavBar` прозрачен; схема видна в образовавшемся промежутке.
Браузерная проверка сравнения пикселей шапки с видимой и скрытой статьёй
воспроизвела дефект до изменения CSS.

Цель — существующая непрозрачная шапка в обеих темах и режимах ширины.
Минимальное решение: фоновый цвет `var(--vp-nav-bg-color)` всему
`.VPNavBar:not(.home)` в `site/.vitepress/theme/custom.css`.
Альтернатива — пересчитывать отступ псевдоэлемента отдельно для каждого
режима Nolebase; она дублирует раскладку плагина и здесь не нужна.
Визуальный эталон — штатная тема VitePress и её токен фона, без изменения
расположения элементов и без изменения оформления главной.

Проверка: совпадение пикселей фона при скрытии/показе статьи, светлая/тёмная
темы, режимы ширины 1/3/4/5, широкое окно и стандартная ширина, поиск,
мобильная шапка и отсутствие влияния на главную. Осмотреть итоговый снимок.
