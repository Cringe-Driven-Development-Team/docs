# Миграция документации на VitePress 2.0.0-alpha.21

Статус: согласовано пользователем 2026-10-31. Реализация ещё не начата.

## Цель и согласованные границы

Перевести `Cringe-Driven-Development-Team/docs` с VitePress `1.6.4` ровно на
`2.0.0-alpha.21`, сохранив работу страниц, схем и навигации. В задачу включены
адаптация `@tp-prepare/vitepress-module-graph` в `TP-Prepare/frontend-packages`,
выпуск его версии и подключение выпущенного пакета в `docs`.

Пользователь выбрал точечную миграцию. Новые возможности Markdown станут доступны
через обновление движка; переписывать под них существующие страницы не требуется.
Установка новых агентных скиллов, редизайн, рефакторинг графа и рендерера Eraser
в эту задачу не входят. Поддержку VitePress 1.x и непроверенных alpha-версий
специально не добавляем. Временная недоступность между интеграциями допустима;
требования безостановочного перехода нет.

## Рассмотренные подходы

1. **Выбран: точечная миграция.** Обновить движок и необходимую конфигурацию,
   проверить существующие интеграции, исправить только доказанные несовместимости,
   выпустить module-graph. Меньше изменений; объём работы с Mermaid выяснится
   при проверке целевой версии.
2. **Отклонён: заранее заменить Mermaid plugin собственным подключением.**
   Убирает внедрение во внутренности VitePress, но добавляет собственную
   интеграцию до подтверждения проблемы.

## Решение

### Движок и конфигурация docs

Закрепить VitePress `2.0.0-alpha.21` точной версией и обновить `bun.lock` штатным
менеджером проекта. Внести обязательные изменения конфигурации и исправить
доказанные регрессии CSS, SSR, типов и сборки. Прямые зависимости, не связанные
с миграцией, отдельно не обновлять; транзитивные изменения lockfile проверить.

Сохранить адреса страниц, формат модулей и схем, меню, русские подписи и
настройки поиска. Особое внимание — CSS reset VitePress 2, локальному поиску,
гидратации графа, шапкам треков и прокрутке к якорям после Mermaid.

### Module-graph

Спецификация изменения пакета хранится рядом с ним:
`TP-Prepare/frontend-packages/docs/superpowers/specs/2026-10-31-vitepress-2-module-graph-design.md`.

Предложение автора спеки: dev dependency и peer dependency VitePress в новой
версии пакета закрепить на `2.0.0-alpha.21`. Это заявляет проверенную цель;
расширять диапазон на другие версии можно после их отдельной проверки.
Изменение требования к VitePress обозначить как breaking change. Конкретную
следующую версию сформирует release-please; вручную её не назначать.

Обновить существующий тестовый сайт и инструкции подключения. Публичные
экспорты, формат данных, CLI и Vue-компоненты менять только при выявленной
несовместимости. Перед выпуском проверить собранный npm-архив вне workspace,
чтобы симлинки не скрыли проблему упаковки.

### Mermaid

Сначала проверить текущий плагин в production build и dev-сервере на целевом
VitePress. Если он работает, сохранить подключение. Его устаревший peer range
явно описать в результатах проверки; предупреждение установщика не считать
доказательством неисправности или совместимости.

Если выявится несовместимость, исправить минимально необходимую часть
подключения. Сохранить существующие блоки `mermaid`, `securityLevel: strict`,
размеры и прокрутку схем, реакцию на тему и повторную прокрутку к якорю.
Отдельный форк или новое расширение сайта заранее не создавать. Способ
конкретного исправления остаётся исполнителю; существенный рост объёма требует
уточнения спеки перед продолжением.

### Интеграция и выпуск

Разрабатывать и проверять оба репозитория можно независимо: для локальной
интеграции docs использовать архив собранного module-graph. Временный путь к
архиву не должен попасть в итоговый манифест или lockfile.

После проверок провести изменение пакета через существующий release-please и
`release.yml`, подтвердить наличие новой версии в npm и соответствие её
манифеста целевой версии VitePress. Затем закрепить выпущенную версию в docs,
обновить lockfile и повторить интеграционную проверку с установкой из реестра.
Интегрировать docs и проверить опубликованный сайт.

## Проверка и приёмка

Для пакета: существующие `build`, `typecheck`, `test`, `test:packages`,
`bun run --filter '*' test:site`; установка и проверка его архива вне workspace.
Дополнять тесты только для обнаруженных дефектов или пробелов в сценариях
перехода. Новую инфраструктуру тестирования не вводить.

Для docs: `bun run typecheck`, `bun run test`, `bun run modules:check`,
`bun run build` и smoke-проверка `site:dev`. Полная сборка включает проверку
Mermaid, генерацию схем, проверку ссылок, якорей и ресурсов. Нативный режим
допустим по правилам репозитория при отсутствии Docker.

В браузере проверить на собранном сайте и в dev:

- граф модуля, фильтры, открытие карточки, архив, шапку трека и подстраницу;
- Mermaid: появление SVG, светлую/тёмную тему, переход между страницами и якорь
  под схемами;
- Eraser: iframe, масштаб, «вписать», полный экран и ссылки HTML/PNG;
- локальный поиск и переход из результата, меню и копирование кода;
- обычную страницу и модуль на узком экране, ссылки и ресурсы под `/` и
  базовым путём превью ветки, отсутствие ошибок гидратации в консоли.

Приёмка: обе рабочие области собираются на точном целевом VitePress, новая
версия module-graph опубликована, docs использует её из npm, CI и проверки
реального сайта после интеграции успешны. Успех сборки отдельно от проверки
в браузере не подтверждает интерактивное поведение.

## Риски и решения исполнителя

Alpha-версия движка и нерасширенный upstream peer range Mermaid остаются
явными ограничениями. В рамках этой задачи дальнейшие alpha-обновления
автоматически не принимаем. Ошибки публикации устранять через существующий
workflow; пакет не публиковать вручную вместо него.

Исполнитель выбирает конкретные минимальные исправления по результатам
проверок, дополнительные регрессионные тесты и браузерные страницы-примеры.
Новые пользовательские возможности и изменение формата данных потребуют
отдельного решения владельца.
