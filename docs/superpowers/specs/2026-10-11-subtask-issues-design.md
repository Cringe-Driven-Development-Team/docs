# Задачи у подзадач на графе модуля и без кнопки «Вписать» — дизайн

## 1. Зачем

Сейчас карточка подзадачи на графе модуля показывает только «Входит в трек» и «Кто», без задач. Пример — трек
Figma: подзадачи «Экран профиля» и «Экран блокнота: …», под каждую заведена задача (figma#5, figma#6). Задачи
видны в карточке трека Figma, а в карточке подзадачи их нет. Плагин `@tp-prepare/vitepress-module-graph`
связывает задачу с треком по полю «Трек» на доске. Подзадача во frontmatter — просто строка, связи с задачей у
неё нет.

Кнопка «Вписать» в углу графа подгоняет масштаб так, чтобы был виден весь граф. По названию это непонятно, и
после загрузки страницы граф и так весь на экране, так что нажатие ничего не меняет. Пользователь принял её за
неработающую. Колеса мыши и перетаскивания хватает.

Цель: клик по кружку подзадачи показывает её задачи (номер, название, статус, спринт, исполнитель), так же
как карточка трека показывает задачи трека. Кнопки «Вписать» больше нет.

## 2. Решения

1. **Связь подзадачи с задачей задаётся явно во frontmatter трека**, полем `issues` у подзадачи. Автоматическое
   сопоставление по названию и отдельное поле на доске отвергнуты: первое молча рвётся при переименовании,
   второе дублирует данные docs в GitHub Projects.
2. **Задача из `issues`, которой нет в снимке доски, сборку не роняет.** Карточка показывает её номер ссылкой на
   GitHub с пометкой «нет на доске». Иначе прод перестал бы собираться, если кто-то просто уберёт задачу с доски.
3. **Кружки на графе не меняются**: без статуса, без колец прогресса. Список задач в карточке трека тоже прежний.
4. **Кнопка «Вписать» удаляется** вместе со своими стилями. Граф по-прежнему сам вписывается после раскладки:
   при загрузке и при смене фильтров (`needFit` в `GraphCanvas.vue`).

## 3. Формат

`tracks/*.md`, поле `subtasks`:

```yaml
subtasks:
  - "Строка — как раньше"
  - title: "Экран профиля"
    issues: [figma#5]
  - title: "Экран блокнота"
    issues: [figma#6]
    subtasks:                 # вложенные: строка или { title, issues }
      - "Строка"
      - title: "Поиск по файлу"
        issues: [frontend#40]
```

- Верхний уровень: строка или `{ title, issues?, subtasks? }`. Вложенный: строка или `{ title, issues? }`.
  Вложенность по-прежнему в один уровень.
- `issues` — необязательный непустой список номеров задач в виде, который пишет снимок доски (`refOf` в
  `src/cli/board.ts`): `репо#N` для репозиториев владельца доски (`board.owner` в `module-graph.yaml`) и
  `владелец/репо#N` для остальных. Регулярка: `^(?:[A-Za-z0-9-]+/)?[A-Za-z0-9._-]+#[1-9][0-9]*$`.
- Ошибки сборки (`ModuleDataError`, текст как у остальных полей):
  - лишний ключ в объекте подзадачи — «нужна строка или { title, issues, subtasks }» (вложенная: «нужна строка
    или { title, issues }»);
  - `issues` не список, пустой список, элемент не строка или не по регулярке — «нужен номер задачи вида
    репо#N или владелец/репо#N»;
  - номер повторяется внутри `issues` одной подзадачи — «задача … повторяется».
- Одна задача у нескольких подзадач — не ошибка.

Модель (`src/model/modules.ts`):

```ts
export type SubtaskLeaf = { title: string; issues: string[] };
export type Subtask = { title: string; issues: string[]; subtasks: SubtaskLeaf[] };
```

Строка разбирается в `{ title, issues: [] }`. Тип `Subtask.subtasks` меняется со `string[]` на `SubtaskLeaf[]`:
это изменение публичного типа, все места, которые читают вложенные подзадачи как строки, переходят на `.title`
(`buildGraph`, `subtaskByNodeId`, `NodeCard.vue`, `TrackMeta.vue`). `subtaskByNodeId` возвращает ещё `issues`.

## 4. Данные доски

`BoardData` (`src/model/board.ts`) получает поле `byRef: Record<string, BoardTask>` — все задачи снимка по
`ref`, до раскладки по модулям. `readBoard` (`src/node/read.ts`) его заполняет. Раскладка `byModule` отбрасывает
часть задач (например, без спринта и без трека), поэтому искать задачу подзадачи в `byModule` нельзя: такая
задача ложно получила бы пометку «нет на доске».

Новая чистая функция в `src/model/board.ts`:

```ts
export type SubtaskIssue = { ref: string; task: BoardTask | null; url: string | null };
export function subtaskIssues(issues: readonly string[], byRef: Readonly<Record<string, BoardTask>>, owner: string | null): SubtaskIssue[];
```

- Задача в снимке: `task` — она, `url` — `task.url`.
- Задачи нет: `task: null`, `url` — `https://github.com/<владелец>/<репо>/issues/<N>`, где владелец берётся из
  номера, а если его там нет — `owner` (`config.board.owner`). Без `board` в конфиге (`owner === null`) и без
  владельца в номере — `url: null`, номер показывается текстом.
- Порядок — как в `issues`.

## 5. Карточка подзадачи

`NodeCard.vue`, ветка подзадачи. После «Входит в подзадачу» и «Подзадачи» — блок задач:

- заголовок «Задачи · N из M готово»; N и M считает `trackProgress` по найденным задачам (задачи «нет на доске»
  в счёт не входят);
- найденные задачи — компонент `TaskList`, как в карточке трека;
- задачи «нет на доске» — строкой под списком: номер ссылкой и пометка «нет на доске»;
- блока нет, если у подзадачи нет `issues` или карточке не передан снимок (`tasks === null` — как у трека:
  снимка нет или у модуля нет спринтов).

`NodeCard` получает снимок через новый проп `byRef: Record<string, BoardTask> | null` из `ModuleGraph.vue`
(`data.board?.byRef ?? null`, но `null`, когда `tasks` равен `null`).

## 8. Что не входит

- Статус задачи на кружке подзадачи и прогресс на графе.
- Задачи подзадач на странице трека (`TrackMeta.vue` только переходит на новый тип).
- Проверка, что номер из `issues` есть на доске, в `module-graph check` (снимка локально обычно нет).
- Автозаполнение `issues` из `/cdd-tasks` — правка скилла, отдельно.

## 9. Проверка

- Тесты плагина (`bun test` в `packages/vitepress-module-graph`):
  - разбор `subtasks`: строка, объект с `issues`, вложенный объект с `issues`; каждая ошибка из §3 с полем и
    текстом;
  - `buildGraph` и `subtaskByNodeId` на вложенных объектах (названия узлов, `issues`);
  - `readBoard` заполняет `byRef` всеми задачами снимка, включая отброшенные раскладкой;
  - `subtaskIssues`: найденная задача, отсутствующая `репо#N` и `владелец/репо#N`, порядок.
- Типы, линтер и сборка пакета — как в CI репозитория.
- docs: `bun run typecheck && bun run test && bun run build`.
- Глазами на превью ветки docs (с `board.json` в сборке Pages): карточка «Экран профиля» показывает figma#5 со
  статусом, кнопки «Вписать» нет, граф вписывается при загрузке.
