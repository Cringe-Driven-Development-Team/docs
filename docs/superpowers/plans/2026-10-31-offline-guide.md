## На что обратить внимание при проверке

1. HTTP 503 ошибочно назван отсутствием сети — текст сохраняет различие HTTP-ответа и сетевого отказа.
2. Первый визит без сети либо удалённый кеш — офлайн-страница не обещается без подготовки SW и кеша.
3. Персональный HTML случайно включён в описываемый precache — архитектура явно исключает его и RPC из кеша SW.
4. Примеры становятся готовым решением для студента — допустимы только блоки Mermaid, без кода, конфигурации и псевдокода приложения.
5. Новые документы не попали в меню либо схемы нечитаемы — проверяются разобранные pages, количество схем и их отображение в собранном сайте.

Каждый пункт проверяется в единственной задаче ниже. Три страницы образуют один учебный раздел:
раздельное добавление незарегистрированных подстраниц нарушило бы проверку модулей.

**Результат:** прежняя страница трека и две зарегистрированные подстраницы с заголовками

- [ ] **Шаг 2. Добавить тест раздела и подтвердить ожидаемый отказ.**

  В `scripts/offline-pages.test.ts` использовать `bun:test`, `readFileSync` и `loadModuleDir`,
  как в существующих тестах страниц и данных. Минимальные проверки:

  ```ts
  test("offline: подстраницы зарегистрированы в порядке чтения", () => {
    const track = loadModuleDir("site/modules").modules
      .find((module) => module.id === "2")?.tracks.find((track) => track.id === "offline");
    expect(track?.pages.map((page) => page.title)).toEqual([
      "Теория офлайн-режима", "Архитектура офлайн-режима Cellestial",
    ]);
  });
  ```

  Другие тесты этого файла проверяют порядок разделов, 10/3 Mermaid-блоков,

  секретов, IPv4 и незакрытого Vue-шаблона. Проверки архитектуры привязать к разделам:
  NetworkOnly и исключение персонального HTML/RPC; отличие HTTP 503 от сетевого отказа;
  ограничение первого визита/удалённого кеша; navigator.onLine как подсказка.
  Не привязывать тесты ко всему тексту дословно.
  `bun test scripts/offline-pages.test.ts` должен упасть на отсутствии новых страниц/pages.
