# Сценарии атак CSRF — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Научить читателя объяснять действующую CSRF-защиту через семь сценариев и пять согласованных вопросов.

**Architecture:** Расширяется существующая страница `/documentation/security/csrf`. Установленные механизмы, браузерные правила и свидетельства проверки имеют явные источники и границы достоверности. Код приложения и генерация OpenWiki не меняются.

**Tech Stack:** Markdown, VitePress, существующая Mermaid, Bun, Chrome, исходники BFF/tRPC и браузерные стандарты.

**Spec:** `docs/superpowers/specs/2026-11-04-csrf-attack-scenarios-design.md` (утверждена).

## Global Constraints

- Одна фактическая страница, семь сценариев из спеки, пять вопросов для каждого.
- Сохранить таблицу cookie, существующие якоря, связь с XSS и одну Mermaid на странице CSRF.
- Не переносить факты из планов без проверки; `415`, `403` и отказ preflight различать.
- Указывать условия cookie, credentials и запроса. Успешная CSRF-проверка не гарантирует сессию, валидный ввод или вызов Go.
- Не менять приложение, планы модуля, зависимости, generated OpenWiki; не создавать аккаунты и не выполнять изменяющие состояние пробы прода.
- Не добавлять тесты на точную редактуру текста. Проверять существенные утверждения воспроизведением и источниками, представление — собранной страницей.

## Review Focus

1. Отказ preflight не выдаётся за выполненную mutation с HTTP 403; простой запрос может отправиться, даже если JavaScript не прочитает ответ (шаги 2–4).
2. Same-site поддомен остаётся cross-origin; отправка cookie зависит и от режима credentials (шаги 2–4).
3. Login CSRF объясняет привязку браузера жертвы к учётной записи атакующего без требования прежней сессии (шаги 2–4).
4. Внешний GET HTML отделён от GET RPC; возможный refresh сессии не называется изменением предметных данных (шаги 2–4).
5. XSS может выполнить запрос с cookie, не читая HttpOnly-cookie; поддельные заголовки в curl не доказывают браузерный обход CSRF (шаги 2–4).
