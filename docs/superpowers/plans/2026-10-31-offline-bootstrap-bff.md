# Регистрация SW и подготовка офлайн-комплекта через BFF — план

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Показать студенту регистрацию SW, источник офлайн-файлов и однозначную политику кеширования.

**Architecture:** На существующей странице архитектуры добавить отдельный подготовительный сценарий перед онлайн-навигацией. BFF публично раздаёт SW и офлайн-комплект; обычные JS/CSS SPA остаются на CDN. Только офлайн-комплект попадает в Cache Storage.

**Tech Stack:** VitePress, Markdown, Mermaid, bun:test; без новых зависимостей.

**Spec:** `docs/superpowers/specs/2026-10-31-offline-bootstrap-bff-design.md` — подтверждена пользователем.

## Global Constraints

- «Сохранить учебное объяснение без готового SW, конфигурации плагина или псевдокода реализации».
- «Публичный стабильный адрес SW — `https://cellestial.ru/sw.js`, scope — `/`».
- Офлайн-HTML: `https://cellestial.ru/offline.html`, публичная статика BFF без сессии, Go API и bootstrap.
- «Итого станет 14 схем: прежние 10 теории и 4 архитектуры».
- Столбец «Кешируем в Cache Storage»: только «Да» или «Нет», без опциональной политики.
- Персональный HTML, RPC/API и остальные ассеты SPA — Нет; офлайн-страница и обязательные ресурсы — Да.
- «Данные треков, задачи GitHub и код самого приложения не меняются»; продолжить уже влитый PR #115 отдельным PR.
- Продолжить ранее выбранный пользователем SDD для раздела; существующий исправленный текст теории сохранить.

## Review Focus

1. Источник файла перепутан с выполнением регистрации: регистрацию инициирует клиентская страница, BFF лишь раздаёт файлы.
2. Регистрация выдана за гарантированную готовность: установка, кеширование, активация и управление страницами явно разделены.
3. CDN base незаметно меняет URL SW: адрес регистрации остаётся app-origin; ассеты SPA продолжают приходить из CDN.
4. Таблица Да/Нет противоречит старой фразе про optional precache: политика во всех затронутых разделах согласована; HTTP-кеш отделён от Cache Storage.
5. Схема и таблица плохо читаются: обязательный осмотр изменённой страницы в светлой и тёмной темах, без фиксированного светлого фона.
