# Сохранение открытых экранов Figma: план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Возвращать посещённый экран без повторной загрузки iframe по инициативе документации.

**Architecture:** Каждый экран получает постоянную позицию в дереве компонента. Iframe
создаётся при первом выборе, далее только скрывается или показывается; посещённость
хранится в экземпляре FigmaEmbed и исчезает при его уничтожении. Существующий общий
tabpanel, вкладки, подпись и ссылка остаются привязаны к активному экрану.

**Tech Stack:** Vue, TypeScript, VitePress, Bun, существующий браузерный CLI/Puppeteer.

**Spec:** `docs/superpowers/specs/2026-11-04-figma-retained-frames-design.md` (согласована).

## Global Constraints

- При открытии страницы создаётся только iframe начальной вкладки QR-кода.
- Один iframe на запись списка экранов. Для текущего списка 2FA предел — четыре; повторные переключения не увеличивают это число. Это не новый глобальный лимит компонента.
- При переключении уже созданные iframe остаются в прежних DOM-позициях с неизменным src.
- Скрытые iframe исключены из клавиатурной навигации и дерева доступности.
- Время жизни сохранённых экранов ограничено экземпляром просмотрщика.
- Новые зависимости не требуются; контент сценариев, список макетов, node-id и файл Figma не меняются.

## Review Focus

- Возврат к экрану во время незавершённой загрузки не создаёт второй запрос/контекст.
- Добавление ранее не открытого экрана перед существующим не перемещает прежний iframe.
- SPA-уход и возврат очищают экземпляры; смена якоря на текущей странице сохраняет их.
- Клавиатурный выбор тоже отмечает экран посещённым; Tab не входит в скрытые iframe.
- Счётчик DOM и heap родительской страницы не выдаются за доказательство отсутствия утечек внутри Figma.

### Task 1: сохранённые iframe и проверка их жизненного цикла

**Files:**
- Modify: `site/.vitepress/theme/FigmaEmbed.vue`.
- Modify: `scripts/check-readability.ts`, функция `checkFigma` и минимальные связанные типы теста.
- Existing checks, unchanged unless required: `scripts/figma-embed-pages.test.ts`, `scripts/figma-embed.test.ts`.
- Read-only caller: `site/modules/2/tracks/2fa-front.md`.

**Interfaces:**
- Сохранить props `screens: { label: string; title: string; url: string }[]`, `initialIndex?: number` (default 0).
- Сохранить `figmaUrls(input: string): { embed: string; source: string }` и проверку всех экранов до SSR-рендера.
- Локальный `selectScreen(index: number): void` отмечает посещённость и меняет выбранный экран;
  его используют и click, и существующий обработчик клавиатуры.
- Тест получает прежние четыре node-id и titles из существующего `checkFigma`; QR — индекс 1.
  Компонент не получает глобальный кэш, таймеры, KeepAlive или поддержку динамической замены списка.

- [x] **1. Добавить падающую браузерную проверку.** В существующей секции `figma` считать
  навигационные запросы по embed URL; тестовый документ содержит изменяемый маркер и
  фокусируемый элемент. После прокрутки виджета в область просмотра загружен только QR.
  Сохранить ElementHandle QR и объект Puppeteer Frame, затем выбрать профиль (индекс 0),
  вернуться к QR и проверить те же узел/Frame/маркер и один запрос на каждый посещённый URL.
  Контроль идентичности: `assert.strictEqual(await qrElement.contentFrame(), qrFrame)`;
  проверять и неизменность документа маркером, поскольку одного Frame недостаточно.
- [x] **2. Подтвердить RED.** Собрать текущую страницу через `bun run site:vitepress`
  (при отсутствии готовых ресурсов — полная сборка), затем
  `CHROMIUM_PATH=/opt/google/chrome/chrome bun scripts/check-readability.ts figma`.
  Ожидается падение сохранения документа/счётчика запросов, а не ошибка инфраструктуры.
- [x] **3. Реализовать сохранение.** В FigmaEmbed создать локальный набор посещённых индексов
  с initialIndex; использовать selectScreen из обоих способов выбора. Рендерить стабильные
  контейнеры по исходному списку; iframe создавать только для посещённых, скрывать неактивные
  через display (`v-show`), не менять src уже созданного экземпляра. Сохранить один общий
  tabpanel и существующие ARIA-связи, оформление, lazy loading и fullscreen.
- [x] **4. Расширить lifecycle-проверки.** Обновить старое ожидание одного iframe:
  после всех посещений — четыре, виден один. Один раз на настольной ширине выполнить
  20 циклов выбора 0→1→2→3 (не повторять нагрузочный цикл для каждой темы/ширины):
  у каждого тот же DOM-узел, Frame и маркер; запросов по одному на экран.
  В отдельном контексте удержать ответ первого нового экрана, переключиться и вернуться
  до разрешения ответа; запрос один, после разрешения отображается тот же экземпляр.
  Освобождать перехваты и handles в finally, чтобы тест сам не удерживал удалённые объекты.
- [x] **5. Проверить навигацию и доступность.** После смены якоря текущей страницы
  iframe сохраняются. Через обычную внутреннюю ссылку перейти на `/modules/2/tracks/2fa`:
  DOM iframe исчезает, соответствующие Puppeteer Frame отсоединены. При SPA-возврате
  есть только новый QR; три цикла ухода/возврата не накапливают дочерние контексты.
  В существующей матрице обеих тем/390/1440 px/узкого режима сохранить проверки
  click, стрелок/Home/End, фокуса, подписи/ссылки и размещения; выбирать активный iframe,
  а не первый в DOM. Проверить Tab через интерактивный тестовый документ: скрытые
  экраны пропускаются; их display:none исключает содержимое из дерева доступности.
- [x] **6. Подтвердить GREEN и сборку.** Запустить `bun run modules:check`,
  `bun run typecheck`, `bun run test`, `bun run build`, затем браузерную секцию `figma`.
  Без Docker: `DIAGRAMS_NATIVE=1 CHROMIUM_PATH=/opt/google/chrome/chrome bun run build`.
  Ожидаются exit 0 и все новые lifecycle/старые UI-проверки PASS. Проверить SSR HTML:
  только начальный iframe, после гидратации нет ошибок. Для вложенной базы
  `SITE_BASE=/branches/docs-figma-retained-frames/` выполнить `site:vitepress`, `index`,

- [x] **7. Отдельно проверить живую Figma и память.** Без подмены внешнего документа

  Маркеры/счётчики тестовой заглушки доказывают жизненный цикл нашего компонента, не отсутствие
  сторонних утечек. Не задавать произвольный порог мегабайт и не менять продукт ради измерений.
