# Учебная документация 2FA — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Метод выбран пользователем. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Дать студентам верхнеуровневую документацию 2FA с требованиями, сценариями и схемами, без готового решения.

**Architecture:** Обзор в `2fa.md`, требования к фронту/BFF в `2fa-front.md`, требования к серверу в `2fa-back.md`. Три Mermaid sequence показывают смысл взаимодействий; одна Eraser deployment — размещение компонентов существующей целевой архитектуры.

**Tech Stack:** Markdown, VitePress 2, Mermaid sequenceDiagram, Eraser JSON, Bun, Docker; существующие компоненты и валидаторы.

**Spec:** `docs/superpowers/specs/2026-11-03-2fa-documentation-design.md` (редакция после уточнения пользователем учебного уровня).

## Global Constraints

- Студент должен понять назначение работы, пользовательские сценарии, ответственность компонентов и критерии результата; способы реализации и проектирование API остаются его работой.
- Не публикуются готовые REST/tRPC-контракты, имена ручек, тела запросов и ответов, HTTP-коды, имена полей/флагов, алгоритмы и псевдокод, параметры криптографии, схемы БД, библиотеки, настройки конфигурации и пошаговое программирование.
- В учебных страницах нет готовых фрагментов кода; исключение — декларативные диаграммы для визуализации общей модели.
- Каждая страница начинает с краткого пояснения назначения и целевого статуса. Страницы не выдают наличие требований или макетов за готовую реализацию.
- Ссылки на существующие задачи остаются источниками конкретных согласованных требований; их содержимое в этой работе не изменяется.
- Frontmatter, исполнители, граф, задачи GitHub, Figma и код приложения не меняются.
- Новые способы 2FA, совместимость со старым клиентом и безостановочная выкладка не добавляются.
- Схемы сопровождаются пояснениями через существующий DiagramSection; никаких новых конвенций или рендереров.
- Нет сессии до успешного входа и нет включения 2FA до подтверждения. Аутентификатор работает локально, сервер не вызывает его API.
- Не добавлять заголовок H1 в тело трека, новые зависимости и тесты, зеркалирующие фразы документа.

## Review Focus

1. Излишняя детализация: ни одна страница/стрелка не содержит готовый API или способ реализации. Проверка каждой задачи — осмотр текста и схем по границе детализации из спеки.
2. Преждевременное включение или вход: подготовка не включает 2FA, второй фактор обязателен после включения, ошибка не меняет состояние. Проверки Task 1/2/3 — матрица сценариев и ветви схем.
3. Один телефон: QR имеет ручную альтернативу, ошибка копирования допускает выделение, возврат продолжает сценарий без обещания сохранности при выгрузке ОС. Проверка Task 2 — текст и sequence.
4. Узкая ширина и длинные подписи: схемы и таблицы читаемы, доступен масштаб, нет переполнения страницы. Проверки Task 2/3 — PNG и браузер на 390/1440 px.
5. Неподтверждённый прод или выдуманные связи: целевой статус виден, у аутентификатора нет серверного API, deployment остаётся схемой модуля. Проверка Task 3 — модель связей и собранные страницы.
