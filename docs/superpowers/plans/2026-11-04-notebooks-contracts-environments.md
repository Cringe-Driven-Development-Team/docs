# Контракты блокнотов и окружения — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Объединить окружения с треком блокнотов и дать на общей странице две таблицы контрактов с JSON-примерами, сохранив bootstrap, сценарии и действующие адреса.

**Architecture:** Существующий `notebook-vps` получает `part_of: file-exec`, а его текст отделяет текущую модель окружений от раннего исследования. Страница `file-exec/contract` показывает полезную нагрузку tRPC и HTTP Go в отдельных таблицах, с общей логикой первоначальной загрузки и сохранением имеющихся диаграмм. Используются существующие HTML-таблицы, CSS и проверки VitePress.

**Tech Stack:** VitePress/Vue Markdown, module-graph frontmatter, Bun tests, существующие Mermaid/Diagram, Docker build, Puppeteer через штатный browser harness; Apidog CLI только для чтения.

**Spec:** `docs/superpowers/specs/2026-11-04-notebooks-contracts-environments-design.md` — согласована 04.11.2026.

## Global Constraints

- Все URL сохраняются; переадресации не нужны.
- Назначения, статусы, спринты, поле «Трек» и Relationships GitHub не меняются.
- Одиннадцать строк: `notebooks.get`; `cells.create`, `cells.update`, `cells.move`, `cells.delete`; `runtime.start`, `runtime.execute`, `runtime.executeAll`, `runtime.stop`, `runtime.activity`, `runtime.updates`.
- Полный состав HTTP-таблицы — 16 строк из раздела «Таблица BFF → backend» спеки, с указанными там Apidog IDs; пути относительно `/api/v1`.
- Таблица описывает полезную нагрузку процедур, а не транспортный JSON-конверт tRPC. Не представлять HTTP-коды Go как коды успешного ответа tRPC.
- Внутренние GET session/queue/events/execution остаются методами Go-клиента; не добавлять браузерные tRPC runtime.get/queue/events/execution.
- Все показанные JSON-блоки синтаксически валидны — без многоточий как JSON-токенов и комментариев.
- Оговорка про hash остаётся видимой до таблиц и в прежнем `#статус-хэша`.
- Не вводить поддержку двух семантик/старых endpoint как обход.
- Существующие схемы не требуют изменения архитектуры из-за этого документационного уточнения. Зависимость от готовности #38 не добавляется.
- Не входят: код frontend/BFF/backend/infra, запись в Apidog, изменения GitHub issues/доски/назначений, новые API, импорт/экспорт ipynb, список/создание блокнотов как отдельные экраны, variables/interrupt/restart UI, новые диаграммы и переработка общих widgets.
- Слияние не входит без отдельного поручения.
