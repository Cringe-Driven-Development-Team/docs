# План: OpenWiki как первый источник контекста

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Агент получает контекст из wiki и завершает поиск, когда ответа достаточно, без проверки свежести и обязательного перечитывания исходников.

**Architecture:** Единое правило в проектных `AGENTS.md`, инструкциях генерации quickstart и действующих пояснениях для пользователей. Опубликованная wiki считается актуальной; актуальность обеспечивает процесс публикации, а не читающий агент. Целевая автоматическая генерация через CI внедряется отдельно.

**Tech Stack:** Markdown, существующие OpenWiki MCP и Bun-проверки репозиториев. Новых зависимостей и runtime-кода нет.

**Spec:** `docs/superpowers/specs/2026-11-04-openwiki-reading-policy-design.md` в репозитории docs.

## Общие ограничения

- Для поиска контекста: `openwiki_search` → `openwiki_read` с ID wiki из результата → остановка при достаточном ответе.
- Не проверять свежесть, не сравнивать SHA и не делать fetch ради обычного чтения. Не считать отсутствие такой проверки недостатком ответа.
- Пробел, противоречие или внесение изменений требуют чтения конкретного исходника. Явную ошибку инструмента не игнорировать.
- Без MCP читать quickstart и Markdown; без wiki искать в каноническом источнике. Не загружать все wiki при старте и не требовать поиск для простой правки известного файла.
- Сохранить различие реализации, проверенных продовых сценариев и состояния стенда прямо сейчас. Планы модулей не включать в wiki.
- Сохранить требования доказательств при генерации wiki и редактировании канонической документации, схем и кода.
- Не менять управляемые блоки установщика, глобальный скилл OpenWiki, runtime, workflows, сгенерированные страницы и checkpoint. Не утверждать, что генерация через CI уже работает.
- Source PR и generated-only PR разделены. Эти изменения сделают текущую wiki устаревшей по штатной проверке; обновление содержимого не входит в план.
- Основные checkout и пользовательские файлы, включая `infra/.apidog/`, сохранить. Работать в отдельных worktree от актуального main, не сбрасывать чужие изменения.

## Фокус проверки

Каждую задачу проверять по следующим сценариям чтением итоговых инструкций; результаты фиксировать в журнале выполнения. Не создавать тесты, проверяющие только наличие фразы в Markdown.

| Сценарий | Ожидаемое поведение |
| --- | --- |
| Wiki полностью отвечает на вопрос | Search → read → ответ; нет проверки свежести, grep и чтения исходника «на всякий случай» |
| В wiki отсутствует нужная деталь | Чтение конкретного документа или кода; широкий поиск только если путь ещё неизвестен |
| Wiki противоречит другому доступному свидетельству | Разрешить противоречие по соответствующему источнику, не игнорировать его |
| Нужно изменить известный файл | Прочитать и изменить исходник; wiki не заменяет проверку изменяемого кода |
| MCP отсутствует | Quickstart → нужная Markdown-страница; при достаточном ответе остановка |

Дополнительные проверки во всех задачах: запрос об устройстве системы не запускает аудит прода; запрос «что работает на проде прямо сейчас» не получает выдуманного подтверждения из wiki; запрос о будущей фиче ведёт к модулям.
