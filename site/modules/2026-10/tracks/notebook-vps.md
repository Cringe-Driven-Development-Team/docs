## Цель

У каждого блокнота своё окружение для исполнения кода. Создаёт и удаляет его бэкенд по действиям
пользователя; devops готовит площадку, на которой эти окружения живут.

## Что сделать

### Бэк — Валентин

- Менеджер окружений в Go на [gophercloud](https://github.com/gophercloud/gophercloud) — SDK OpenStack:
  создать сервер, дождаться готовности, удалить.
- Жизненный цикл: когда поднимать, когда гасить простаивающее, сколько окружений можно одному
  пользователю, что делать, если создание упало.
- Ходит в API OpenStack Selectel напрямую, под сервисным пользователем. Pulumi бэку не нужен.
- Сеть, security group и образ берёт готовыми из стека devops — по их id.

### Devops — Денис (Pulumi)

То, что живёт долго:

- отдельная сеть и security group для окружений без доступа к нашим VPS, Postgres и частной сети —
  в окружении исполняется чужой код;
- образ рантайма;
- сервисный пользователь с правами только на этот проект и квоты — чтобы ошибка в цикле не подняла
  сотню машин;
- мониторинг «сирот»: серверы, которые бэк создал и не удалил, и алерт на них;
- id сети, группы и образа — в outputs стека для бэка.

## Почему бэк, а не Pulumi

Pulumi описывает долгоживущую инфраструктуру со стейтом и блокировкой: `pulumi up` на каждый блокнот —
медленно и упирается в блокировку стейта, а стейт копит ресурсы, которые живут минуты. Наши VPS сейчас
создаются через `@pulumi/openstack`
([`pulumi/index.ts`](https://github.com/Cringe-Driven-Development-Team/infra/blob/2f97437/pulumi/index.ts)) —
это тот же API OpenStack, в который бэк пойдёт напрямую.

## Открытые вопросы

- Отдельная VPS на блокнот или контейнеры на пуле машин: VPS поднимается минуты.
