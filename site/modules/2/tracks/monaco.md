## В этом модуле — редактор и сохранение {#в-этом-модуле-—-база}

[frontend#37](https://github.com/Cringe-Driven-Development-Team/frontend/issues/37) отвечает за `code` и `markdown`,
создание, изменение, перемещение и удаление ячеек по стабильному ID. Код и Markdown редактируются как обычный
текст, без вставки source через HTML. Базовый ввод не требует активного runtime.
Черновик хранится отдельно от подтверждённого исходника; автосохранение, очередь мутаций и конфликты
общие для всех ячеек. Лимит исходника — 65 536 байт UTF-8. В текущем коде clipboard paste сокращается до лимита до вставки; oversized draft из другого пути ввода остаётся для исправления, а серверный 413 отклоняет запись. [Различия сценариев](/documentation/notebooks/editing).
При конфликте #37 приостанавливает сохранение, получает свежий снимок без потери черновиков и показывает
диалог «Загрузить серверную версию» / «Сохранить мой текст» с предупреждениями о последствиях.
Закрытие диалога оставляет плашку «Разрешить конфликт»; повторный `409` использует тот же диалог.

[frontend#38](https://github.com/Cringe-Driven-Development-Team/frontend/issues/38) добавляет подсветку Python
поверх того же ввода и безопасный Markdown preview. Подсветка не меняет source; исходный HTML в Markdown
показывается текстом, опасные ссылки и исполняемый HTML не допускаются. Preview строится из локального текста;
переключение режима не подтверждает сохранение. Сохранение и конфликты переиспользуются из #37.

Подсветка была выделена в [#166](https://github.com/Cringe-Driven-Development-Team/frontend/issues/166) и интегрирована [PR170](https://github.com/Cringe-Driven-Development-Team/frontend/pull/170). Текущий код включает подсветку Python fenced blocks Markdown и отступы; [описание реализации](/documentation/notebooks/editing) точнее прежней границы #38.

Ячейки растут по содержимому; вертикально прокручивается страница, длинная строка кода — только внутри
редактора по горизонтали. Клавиатура, IME и телефон 360 px входят в проверку задач.
Макеты: [ввод кода](https://www.figma.com/design/7iaVDGiwzQk2vZIB5ogVlq/Cellestial?node-id=496-14407),
[исходник Markdown](https://www.figma.com/design/7iaVDGiwzQk2vZIB5ogVlq/Cellestial?node-id=496-14776),
[просмотр Markdown](https://www.figma.com/design/7iaVDGiwzQk2vZIB5ogVlq/Cellestial?node-id=496-14596).

## Интерфейс для исполнения

С исполнителем [frontend#51](https://github.com/Cringe-Driven-Development-Team/frontend/issues/51) сначала
согласуйте `notebooks.get`, ID и source ячеек, dirty/saving/error/conflict, сигнал редактирования и ожидание
сохранения выбранных исходников и структурных операций. Исполнение запускает только сохранённый код;
ошибка или конфликт сохранения не разрешает запуск черновика. Статус runtime не скрывает несохранённые правки.
При конфликте ▶ ячейки и «Запустить всё» открывают общий диалог #37 без отправки исполнения.
После выбора серверной версии или сохранения своего текста пользователь повторно нажимает запуск.
Без конфликта обычное нажатие ждёт сохранения и запускает код; второй клик не требуется.

#51 может начать на фикстурах этого интерфейса до готовности #37 и не ждёт #38.
Markdown preview и подсветка проверяются отдельно, затем вместе с общим редактором.
Импорт `.ipynb` не нужен: сценарий начинается с пустого блокнота; интеграция сохранения проверяется через BFF и backend.
