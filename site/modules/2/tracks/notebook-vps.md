Окружение создаётся для runtime-сессии по действию «Запустить окружение». Создание самого блокнота
не требует VPS. Общий сценарий и схема компонентов — в треке [«Блокноты: редактор и исполнение»](./file-exec),
контракты фронта, BFF и Go — в документе [«Сохранение и исполнение»](./file-exec/contract).

::: info Граница реализации на 04.11.2026
Provisioning и агент уже есть в коде backend. Пользовательские сессии и сохранение результатов
связывает [backend#13](https://github.com/Cringe-Driven-Development-Team/backend/issues/13).
Наличие компонентов не означает завершения этого трека, выкладки или проверки всей цепочки на проде.
:::

Срез 08.11.2026 отдельно объясняет [освобождение слота до очистки](/documentation/notebooks/execution#cleanup) и постоянный PostgreSQL вместо исторической S3-модели. Свидетельство от 04.11.2026 выше сохраняет свою дату.

## Договорились

[Модуль provisioning в Go](https://github.com/Cringe-Driven-Development-Team/backend/blob/ac2c7d4aeaf1f084ac6cd3c1e76ea114ddd2907c/docs/runtime-provisioning.md#L1)
создаёт отдельную VPS сессии через OpenStack API и настраивает её через Ansible. Воркер работает внутри
Go API; отдельный сервис-оператор для этого сценария не требуется. Runtime-сессии используют
[EnvironmentService: RequestCreate, Get, RequestDelete](https://github.com/Cringe-Driven-Development-Team/backend/blob/ac2c7d4aeaf1f084ac6cd3c1e76ea114ddd2907c/internal/runtime/usecase/contract.go#L29).
Создание и удаление асинхронны: принятие команды ещё не означает готовность окружения или завершение очистки.

[Runtime-агент](https://github.com/Cringe-Driven-Development-Team/backend/blob/ac2c7d4aeaf1f084ac6cd3c1e76ea114ddd2907c/runtime-agent/README.md#L1)
запускает Docker-контейнер с Jupyter/kernel на этой VPS. Агент не создаёт машины, не обращается к S3/PostgreSQL
и не изменяет ipynb. Исходники, события и результаты сохраняет Go; удаление VPS не должно удалять
сохранённые результаты блокнота.

По целевому сценарию backend#13 остановка пользователем, простой или подтверждённый сбой завершают
сессию и инициируют очистку окружения. Остановка контейнера агентом сама по себе VPS не удаляет.
Чтение состояния, polling и heartbeat не считаются активностью пользователя. Ошибка очистки остаётся
явным состоянием, а не сообщением об успешно освобождённых ресурсах.

[Граница с infra](https://github.com/Cringe-Driven-Development-Team/backend/blob/ac2c7d4aeaf1f084ac6cd3c1e76ea114ddd2907c/docs/runtime-provisioning.md#L8)
описывает роли Ansible, сетевую политику и передачу необходимых артефактов backend. Пользовательские
окружения создаются через API облака; Pulumi для каждого запуска блокнота не вызывается.

## Открытые вопросы

Выбор Kubernetes, Docker на общих хостах или отдельной VPS относился к
[исходному исследованию окружений](./runtime-grooming). Текущая модель использует VPS сессии с Docker/kernel;
перечисленные варианты не являются дополнительными требованиями к реализации.

Сетевую реализацию и её проверку нужно сверять с
[контрактом backend/infra](https://github.com/Cringe-Driven-Development-Team/backend/blob/ac2c7d4aeaf1f084ac6cd3c1e76ea114ddd2907c/docs/runtime-agent-network.md#L1).
Эта страница не подтверждает завершение сетевых работ или исследования. После интеграции backend#13
нужно проверить запуск, исполнение, остановку/простой, очистку ресурсов и повторное открытие
с сохранёнными результатами. Фронт может разрабатываться по согласованным контрактам независимо.
