## Выбор прежнего релиза

Оператор открывает ручной Rollback workflow в GitHub Actions на `main` и вводит
**полный Git SHA** прежней версии. Кандидат — версия с успешным production
Deployment: образ мог быть опубликован в GHCR, но ни разу не пройти проверку
прода. Кнопка «↩️ Откатить» в Telegram только открывает страницу workflow и
ничего не переключает сама. Старое Telegram-сообщение не определяет цель.

До доступа к VPS workflow проверяет формат SHA, находит успешный Deployment с
digest нужного backend package и подтверждает, что образ по digest доступен в
GHCR. Если для одного SHA записаны разные digest, цель неоднозначна: workflow
отказывает, а не выбирает один из образов молча. Неверный SHA, отсутствие
успешной записи и недоступный образ тоже дают отказ до VPS.

## Переключение и проверка

После предварительной проверки workflow входит в тот же `production` environment,
что и обычная выкатка. Оба запуска используют одну concurrency-группу и
ограничение `PRODUCTION_ENABLED`. Перед переключением читается образ
**фактически запущенного** API-контейнера, а не предполагаемая версия из
последнего сообщения или файла конфигурации.

Далее вызывается тот же playbook Ansible с `backend_image_ref` по digest.
После запуска подтверждаются образ нового контейнера, его `healthy` и ответ
публичного API через HTTPS. Только после этих проверок откат получает статус
`success` в GitHub Deployment и успешную карточку в Backend / Releases.
Автоматического отката при ошибке нет.

## Если что-то пошло не так

| Этап | Что можно утверждать |
| --- | --- |
| Цель не прошла предварительную проверку | VPS не трогали; workflow сообщает причину отказа |
| Подготовка или переключение прервались | Показывается подтверждённый запущенный образ либо «неизвестно» |
| Новый контейнер запущен, но проверка не прошла | Указаны этап сбоя и ссылка на логи; успех не объявляется |
| Образ и API проверены, а отправка в Telegram не удалась | Deployment остаётся успешным; ошибка уведомления видна в workflow |

Карточка не подменяет наблюдение за контейнером догадкой. Если состояние
производственного API нельзя подтвердить, она показывает «неизвестно» и
ссылку на логи запуска.

Откат образа не откатывает схему и данные PostgreSQL.
