# Страницы сайта VitePress

Применяй при правке `site/**/*.md`, меню в `site/.vitepress/config.mts`, переадресаций в
`scripts/build-index.ts`. Поля frontmatter треков и модулей (`do`, `subtasks`, `pages`, …) — скилл
`docs-modules`; JSON схем в `diagrams/` — скилл `eraser-diagrams`.

## Адреса и ссылки

- Сайт под `/docs/`, `cleanUrls`: `site/a/b.md` → `/docs/a/b` (файл сборки `a/b.html`),
  `site/a/index.md` → `/docs/a/` (`a/index.html`).
- Ссылка внутри сайта — от корня без `/docs/` (`/modules/2/tracks/bff`) или относительная
  (`./contract`, `../bff#якорь`), без `.md`. База подставится сама, и ссылка работает в превью ветки.
- Ссылку на несуществующую страницу роняет сборка VitePress. Якорь (`#…`) проверяет только
  `bun run site:check` внутри `bun run build`; в `bun run test` его нет — см. «Тесты страниц».
- Модули (`site/modules/`) — план; остальные разделы — как работает прод. Сделанный трек не правится:
  сверху плашка `::: info` «Сделано. Как работает сейчас — [раздел]» (`AGENTS.md`).
- Новая страница вне модулей — файл в `site/` и пункт `sidebar` в `site/.vitepress/config.mts`. Меню
  модулей строится само.

## Подстраница трека

- Файл `site/modules/<N>/tracks/<id>/<page>.md`, `<page>` — строчная латиница, цифры, дефис; во
  frontmatter обязателен `title` — это пункт меню и строка «Документы» в шапке трека.
- Запиши `<page>` в `pages` трека `tracks/<id>.md`: порядок `pages` — порядок в меню. Файл без записи или
  запись без файла — ошибка `bun run modules:check`.
- Со страницы трека на подстраницу — `./<id>/<page>`; с подстраницы на трек — `../<id>#якорь`, на соседнюю
  — `./<page>#якорь`.

## Схема на странице

- `<Diagram name="<имя>" />`, `<имя>` — путь JSON от `diagrams/` без `.json`: `deployment`,
  `modules/2/bff-contract`. Компонент встраивает `<имя>.html` с масштабом.
- Схема плана модуля — `diagrams/modules/<N>/`; папка должна быть в `HIDDEN_FOLDERS`
  (`site/.vitepress/diagram-names.ts`), для нового модуля добавь `modules/<N>`.
- Схема корня (прод) — имя в `ROOT_NAMES` и раздел с `<Diagram>` на `site/architecture/index.md`
  (тесты `scripts/build-index.test.ts`, `scripts/architecture-page.test.ts`).
- Mermaid — блок ` ```mermaid `; синтаксис проверяет `bun run mermaid` в сборке.

## Ловушки VitePress

Markdown страницы — шаблон Vue. Ошибки ниже видны только в собранной странице: `bun run test` и
`modules:check` их не ловят.

1. **`{{ … }}` вне блока ` ``` ` — выражение Vue.** В тексте и даже в строковом коде
   `` `{{ app_domain }}` `` Vue подставит значение — имя пропадёт или сборка упадёт. Блоки ` ``` ` VitePress
   защищает сам. В тексте пиши `<code v-pre>{{ app_domain }}</code>`. Касается Jinja/Ansible, Go
   templates, Helm, `${{ }}` GitHub Actions.
2. **Двоеточие становится эмодзи** везде, кроме обратных кавычек и блоков кода — значит, и внутри
   `<code v-pre>`: `:$`, `:/`, `:D`, `:P`, `:o`, `:s` после пробела или знака (`}:${TAG}` → `}😒{TAG}`) и
   `:слово:` с именем эмодзи (`a:new:b` → `a🆕b`). Двоеточие пиши сущностью: `{{ img }}&#58;${TAG}`.
3. **`<латиница>` вне кода — HTML-тег**: `<name>` в тексте роняет сборку `Element is missing end tag`.
   Плейсхолдер — в обратных кавычках или `&lt;name&gt;`.
4. **Якорь** — `id` заголовка по `slugify` VitePress: NFKD без диакритики (`й` → `и`, `ё` → `е`); любая
   серия пробелов и знаков `` ~`!@#$%^&*()-_+=[]{}|\;:"'“”‘’<>,.?/ `` → один `-`, `-` по краям срезается;
   ведущая цифра получает `_`; всё строчными. `«»` и `—` остаются: `## 2. Шаги` → `#_2-шаги`,
   `## Йод — ёлка` → `#иод-—-елка`, `## Как BFF «работает»: шаги` → `#как-bff-«работает»-шаги`.
   Руками id не сочиняй: возьми его из собранной страницы (`bun run build`, затем
   `grep -o 'id="[^"]*"' dist/<путь>.html`); битый якорь в `<a href>` уронит `bun run build` (`site:check`).

Проверка ловушек 1–3 — по собранному HTML: `bun run build`, затем
`grep -o '<code v-pre>[^<]*' dist/<путь>.html` и поиск нужного текста в `dist/<путь>.html`.

## Тесты страниц

Образец — `scripts/bff-pages.test.ts`: страница читается как текст, проверки — по разделам.

- Новая или переписанная страница — тест `scripts/<тема>-pages.test.ts`: порядок разделов `##`, ключевые
  имена и решения, нет секретов и реальных IP (репозиторий публичный), нет `{{` в строковом коде вне
  блоков.
- **Каждая ссылка с `#якорем`, которую ты добавил, — пара в тесте**: ссылка есть на странице, заголовок-
  цель есть на целевой странице (образец — тест «ссылки на соседей ведут на существующие заголовки»).
  Так переименование заголовка упадёт в `bun run test`, а не на проде.
- Меняешь заголовок или фразу — `grep -rn "<текст>" scripts/*.test.ts site`: тест и ссылки на якорь
  правятся в том же коммите.

## Переезд и удаление страницы

**Любой опубликованный адрес** (страница есть на `main`), который пропадает или меняется, получает
переадресацию со старого адреса: переименование файла, перенос в другой раздел или модуль, удаление,
переименование трека или записи в `pages`. Подстраницы трека — тоже, каждая своей строкой.

1. Строка в `PAGE_REDIRECTS` (`scripts/build-index.ts`): `{ file: "<старый путь>.html", target: "<цель>" }`.
   - `file` — путь от корня сайта без `/docs/`: `modules/2/tracks/x.html`, для `index.md` —
     `<каталог>/index.html`.
   - `target` — **относительный**, от каталога `file`: столько `../`, сколько каталогов в `file`, затем
     новый путь страницы без `.html` (страница `index.md` — путь каталога со `/` на конце: `../modules/3/`,
     не `…/index`); для HTML схемы — с `.html`. Абсолютный `/docs/…` ломает превью
     веток; тест запрещает `/` в начале.
   - Удалено без замены — цель: ближайшая живая страница (родительский трек, граф модуля
     `modules/<N>/`, раздел).
   - Сверка цели: `node -e 'console.log(new URL("<target>", "https://x/docs/<file>").pathname)'` печатает
     новый адрес.
   - Старый адрес не должен совпасть с живой страницей: сборка падает «файлы VitePress совпали с файлами
     схем».
   - `bun run build` (`site:check`) проверяет и ссылку страницы-переадресации: цель, которой нет, роняет
     сборку.
2. Тот же список в `toEqual` теста «PAGE_REDIRECTS» в `scripts/build-index.test.ts`.
3. Ссылки внутри сайта на старый адрес поправь на новый: `grep -rn "<старый путь>" site scripts`.
   Переадресация — для внешних ссылок и закладок, не для своих страниц.
4. Удалена схема — её `<имя>.html`: строка в `PAGE_REDIRECTS` с целью `.html` на живую схему (тест
   проверяет, что JSON цели есть). Удалена папка схем — убери её из `HIDDEN_FOLDERS` и добавь в
   `LEGACY_FOLDERS` (`site/.vitepress/diagram-names.ts`): старые якоря индекса `#<папка>/<схема>` ведут на
   `<папка>/<схема>.html`, а оттуда — `PAGE_REDIRECTS`.
5. Сменился номер модуля целиком — `MODULE_MOVES` в том же файле, по строке на каждую страницу не нужно;
   его тоже держит `expect(MODULE_MOVES).toEqual` в `scripts/build-index.test.ts` — правь вместе.

## Факты о коде других репозиториев

Утверждение о коде — ссылкой на файл и строку на конкретном SHA:
`https://github.com/<владелец>/<репо>/blob/<sha>/<путь>#L<n>` (или `#L<a>-L<b>`).

1. SHA: `gh api repos/<владелец>/<репо>/commits/<ветка> --jq .sha`.
2. Прочитай файл на этом SHA и найди строку:
   `gh api -H "Accept: application/vnd.github.raw" "repos/<владелец>/<репо>/contents/<путь>?ref=<sha>" | sed -n '<a>,<b>p'`.
3. Номер строки и текст ссылки — из этого вывода, не из памяти и не из локального клона (он отстаёт).

## Сборка, PR и превью

- Перед коммитом: `bun run typecheck && bun run test && bun run build` (`build` — в Docker, как в CI;
  без Docker `DIAGRAMS_NATIVE=1 bun run build`).
- Ветка и worktree в `.claude/worktrees/<имя>`, PR в `main`. Описание PR — разделы «Что», «Решения»,
  «Проверка» и ссылка на превью:
  `https://cringe-driven-development-team.github.io/docs/branches/<slug>/<путь>`; `<slug>` — имя ветки,
  где всё, кроме латиницы, цифр, `.`, `_`, `-`, заменено на `-` (`docs/x` → `docs-x`). Точный адрес —
  в списке `…/docs/branches/`.
- Push в ветку запускает workflow Pages на ней: в проверках PR видна только job `dispatch`, она лишь
  запускает Pages на `main`. Превью собирает этот запуск на `main` (вкладка Actions): `main` и все живые
  ветки, на превью всех веток вместе — 30 минут, на шаг — 5. Не уложилась — ветка в списке «не
  собралась» с шагом `time budget`. Pages кэширует 10 минут — Ctrl+F5.
- Превью нет: найди ветку в списке `…/docs/branches/` и шаг, на котором она упала. Упала на своём шаге —
  повтори `bun run build` локально и чини. `time budget` — не твоя ошибка: проверь локальной сборкой, а
  после мержа — на проде `https://cringe-driven-development-team.github.io/docs/<путь>`.
- Влитые ветки удаляются сами, их превью пропадает со следующей сборкой — после мержа проверяй прод.
