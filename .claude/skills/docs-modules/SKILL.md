# Данные модулей и треков

Применяй при любой правке `site/modules/**`: frontmatter треков и модулей, `people.yaml`,
`module-graph.yaml`. Текст страниц, ссылки, подстраницы как документы и переадресации старых адресов —
скилл `docs-site`.

Формат задаёт пакет `@tp-prepare/vitepress-module-graph`: описание —
`node_modules/@tp-prepare/vitepress-module-graph/README.md`, проверки —
`node_modules/@tp-prepare/vitepress-module-graph/dist/model/modules.mjs`. Поля, которых там нет, не
выдумывай: **неизвестный ключ во frontmatter трека пакет молча пропускает** — `check` зелёный, а на графе
ничего не появилось.

## Что где лежит

- `site/modules/people.yaml` — люди: `login` (логин GitHub, регистр важен), `name`, `role`, `area`,
  `mentor: true` только у менторов. Порядок — порядок на графе. Лишний ключ — ошибка.
- `site/modules/module-graph.yaml` — направления (`areas`), стороны (`sides`), шаблон спринта
  (`Sprint {n}`), доска (`board`). Без просьбы не трогай.
- `site/modules/<N>/index.md` — модуль: `title`, `sprints` (`[Sprint 9, Sprint 10]`), `aside: false`, в
  тексте `<ModuleGraph />`. Спринт — только в одном модуле: задача уходит в первый модуль, где он
  найден.
- `site/modules/<N>/tracks/<id>.md` — трек; `id` — имя файла: строчная латиница, цифры, дефис.
- `site/modules/<N>/tracks/<id>/<page>.md` — подстраницы трека (см. `pages`).
- `site/modules/board.json` — снимок доски, в `.gitignore`, его делает CI. Не коммить.
- Трек сделан — его страницы не правятся (`AGENTS.md`, «Что где лежит»).

## Поля трека

| Поле | Форма | Правила |
| --- | --- | --- |
| `title` | строка | обязательно |
| `label` | строка | подпись на графе; нет — берётся `title` |
| `area` | ключ `areas` | `front`, `back`, `devops`, `fullstack`, `team`; у `fullstack` исполнители (с подтреками) обязаны закрыть стороны `front` и `back` |
| `do` | `логин: сторона` | сторона из `sides`: `front`, `back`, `devops`, `team`; логин есть в `people.yaml`; если поле есть — не пустое |
| `mentors` | список логинов | у каждого `mentor: true` в `people.yaml`; не исполнитель этого же трека; без повторов |
| `subtasks` | список | элемент — строка или `{ title, issues, subtasks }`; вложенный — строка или `{ title, issues }`; глубже нельзя; других ключей нет; соседние `title` не повторяются |
| `issues` | список `репо#N` | **только внутри подзадачи** (любого уровня); не пустой, без повторов |
| `part_of` | id трека | родитель в том же модуле; родитель сам не подтрек (один уровень) |
| `related` | список `{ track, why }` | оба непустые; трек того же модуля, не сам, не родитель и не подтрек (связь уже есть через `part_of`) |
| `pages` | список id | подстраницы: на каждую запись файл `tracks/<id>/<page>.md` с `title`; каждый файл каталога записан; порядок — порядок в меню |

- Трек без `do` допустим, только если у него есть подтреки с исполнителями: тогда исполнители родителя —
  исполнители подтреков.
- `issues`: свой репозиторий организации — `репо#N` (`frontend#44`, `infra#46`); чужая организация —
  `владелец/репо#N`. Регистр и префикс владельца доски не важны. Одна задача может стоять у нескольких
  подзадач.
- У трека нет `issues`, `status`, `sprint`, `progress`: такие ключи пакет пропустит молча. `help` —
  ошибка («поле заменено на `mentors`»).
- Строки с `:`, `#` в начале, кавычками — в двойных кавычках, как в соседних треках.
- Заголовок `# …` в тексте трека не нужен: шапку рисует пакет.

## Как задача попадает на граф

Доска — GitHub Projects из `module-graph.yaml` (`board`: организация, номер проекта, поле `Трек`).

- **Задача → трек**: на доске у задачи поле «Трек» = `id` трека. В файле трека задачи трека не пишутся.
  Sub-issue без своего «Трека» берёт его у родительской задачи. Значения поля «Трек» CI пополняет из
  файлов (`module-graph board sync`, job `board` в `.github/workflows/pages.yml`, только на `main`).
- **Задача → модуль**: по спринту задачи — модуль, в чьих `sprints` он есть; без спринта — текущий
  модуль. Задача с «Треком», которого нет в её модуле, на граф трека не попадает.
- **Задача → подзадача**: номер в `issues` подзадачи. Карточка подзадачи покажет задачу и без доски
  («— нет на доске»), но в прогресс трека задача идёт только по полю «Трек» на доске.
- Переименовал `id` трека — задачи на доске остались со старым значением «Трека» и пропали с графа.
  Это правка доски: скажи пользователю.

## Чего не делать

- Не меняй на доске статусы, спринты, поле «Трек», исполнителей и не заводи задачи без явной просьбы:
  изменения задач уходят уведомлениями в Telegram команды, на доске их видят все. По просьбе — скилл
  `cdd-tasks`.
- Не запускай `module-graph board sync` локально: он переписывает список значений поля на доске.
  Снимок для себя (только чтение):
  `GH_TOKEN="$(gh auth token)" bunx module-graph board snapshot site/modules/board.json`.

## Удаление, слияние, перенос трека или подтрека

1. Найди все упоминания: `grep -rn "<id>" site scripts README.md`. Ищешь:
   - `related: - track: <id>` в других треках — иначе `трека <id> нет в модуле <N>`;
   - `part_of: <id>` у подтреков — иначе та же ошибка; подтреки переезжают вместе с родителем или
     становятся самостоятельными (убрать `part_of`, проверить `do`);
   - ссылки в тексте страниц (`](/modules/<N>/tracks/<id>`, `](./<id>`) — битая ссылка роняет сборку
     VitePress;
   - тесты `scripts/*.test.ts`, где назван трек или его подзадачи.
2. Каталог `tracks/<id>/` уходит вместе с треком, `pages` — вместе с ним. Каталог без файла трека —
   ошибка `check`.
3. Родитель без `do` теряет подтрек — у него должен остаться подтрек с исполнителями, и у `fullstack` —
   обе стороны. Иначе дай родителю `do`.
4. Перенос в другой модуль: `related` и `part_of` работают только внутри одного модуля — связи со
   старыми соседями убери или перенеси соседей тоже.
5. Слияние: подзадачи и их `issues` — в оставшийся трек; `related` других треков перенаправь на него;
   связь трека с самим собой — ошибка.
6. Адрес страницы трека и подстраниц изменился или пропал — переадресация со старого адреса, скилл
   `docs-site` («Переезд и удаление страницы»).

## Тест данных `scripts/modules-data.test.ts`

Тест держит реальные данные: число треков модуля 2 (`toHaveLength`, вместе с подтреками), нагрузку
каждого человека `[doing, mentoring]` в модуле 2, подзадачи, `issues`, `part_of`, `related`, `do`
названных треков, заголовки и спринты модулей.

- `doing` — число треков модуля, где логин прямо в `do` (подтрек — отдельный трек; родитель без `do` не
  считается), `mentoring` — число треков, где логин в `mentors`.
- В нагрузке — каждый логин из `people.yaml`, без треков — `[0, 0]`.
- Правка, которая меняет что-то из этого, **правит тест в том же коммите**. Ожидание посчитай по своей
  правке, затем сверь с выводом теста: разница — ровно твоя правка. Чужое расхождение — не подгоняй,
  разберись.
- Новую привязку, ради которой правка (подзадача → задача, подтрек → родитель), закрепи строкой в тесте,
  как в тестах «Monaco» и «Figma».

## Проверка

1. `bun run modules:check` → `modules ok: <N> модул…, <M> трек…`. Ошибка — одна строка
   `<файл>: <поле> — <что не так>`. В Claude Code проверку запускает хук после каждой правки, в
   остальных агентах — pre-commit `lefthook`; прогони сам всё равно.
2. `bun test scripts/modules-data.test.ts`.
3. Убедись, что разобралось то, что ты задумал, а не пропущено молча:
   `bun -e 'import {loadModuleDir} from "@tp-prepare/vitepress-module-graph/node"; const m = loadModuleDir("site/modules").modules.find(m => m.id === "<N>"); console.log(JSON.stringify(m.tracks.find(t => t.id === "<id>"), null, 2))'`.
4. Перед коммитом: `bun run typecheck && bun run test`; поменялись ссылки или страницы — ещё
   `bun run build`.

## Ошибки `check` и что делать

| Сообщение | Причина |
| --- | --- |
| `логина X нет в people.yaml — может быть, Y?` | регистр логина или человека нет в `people.yaml` |
| `X не ментор: в people.yaml нет mentor: true` | в `mentors` не ментор — он в `do` или добавь `mentor: true` по просьбе |
| `X уже исполнитель` | один логин в `do` и `mentors` трека |
| `нужны исполнители со сторон front, back` | у `fullstack` нет одной из сторон (с подтреками) |
| `нужен хотя бы один исполнитель … или подтреки через part_of` | нет `do` и нет подтреков с `do` |
| `трека X нет в модуле N` | `related`/`part_of` на удалённый трек или трек другого модуля |
| `X сам подтрек: вложенность — один уровень` | `part_of` на подтрек |
| `X — родитель или подтрек, связь уже есть через part_of` | лишний `related` |
| `нет файла <id>/<page>.md` / `подстраницы нет в pages трека` | `pages` и файлы каталога разошлись |
| `нужна строка или { title, issues, subtasks }` | лишний ключ в подзадаче или третий уровень |
| `нужен номер задачи вида репо#N или владелец/репо#N` | `issues` пустой, не список или номер не того вида |
| `нужен формат Sprint N` | спринт модуля не по шаблону |
